# 문서 기반 수집 시연용 예시 문서

`API 수집하기 → 문서 기반` 에서 끌어다 놓을 파일들이다.
실제 활용가이드가 배포되는 형태에 맞춰 **PDF** 로 둔다. 원본 텍스트는 `src/`
에 있고, `build-pdf.py` 로 다시 굽는다.

| 파일 | 보여주는 것 | 기대 결과 |
| --- | --- | --- |
| `01_기상청_단기예보조회서비스_활용가이드.pdf` | 공공 활용가이드 표준 서식 | 오퍼레이션 2건 (`getUltraSrtNcst`, `getVilageFcst`), 파라미터 각 8개 |
| `02_사내_회의실예약_API_명세서.pdf` | 포털에 없는 사내 문서 · GET 이 아닌 메서드 | 오퍼레이션 3건 (GET / POST / DELETE) |
| `03_보도자료_공공데이터_개방계획.pdf` | 명세가 없는 문서 | 0건 — "API 명세를 찾지 못했습니다" |
| `04_국토교통부_건축물대장_활용가이드(스캔본).pdf` | 글자 레이어가 없는 스캔 PDF | 0건 — "PDF 에서 글자를 찾지 못했습니다" |

03·04 는 실패 사례가 아니라 **보여줘야 할 장면**이다. 문서 기반 수집은 LLM 이
읽는 만큼, 없는 엔드포인트를 지어내지 않는다는 것을 같은 화면에서 증명한다.
04 는 그중에서도 문서가 열리기 전에 걸리는 경우다 — 빈 글자를 LLM 에 넘기면
모델이 그럴듯한 명세를 만들어내므로 `extract_text` 단계에서 막는다
(`services/doc_collector.py`).

## 다시 굽기

원본을 고쳤으면 PDF 를 다시 만든다. Chrome 헤드리스만 쓰므로 설치할 것이 없다.

```
python3 build-pdf.py
```

`src/*.md|txt` 는 글자 레이어가 있는 PDF 로, `src/scan/*` 는 이미지만 있는
PDF 로 굽는다.

## Azure OpenAI 없이 시연할 때

`apps/backend/.env` 에 `AZURE_OPENAI_*` 가 없으면 규칙 기반 폴백이 돈다
(`services/doc_collector.py:_rule_based`). 01·02 는 `요청주소:` 와
`항목명(국문) | 항목명(영문) | ...` 파이프 표를 갖추고 있어 PDF 로도 폴백이
읽어낸다. 단, 폴백은 문서 안의 파라미터를 모든 오퍼레이션에 똑같이 붙이고
메서드를 GET 으로 고정하므로 그 사실이 경고로 붙는다. 03 은 이때
"Azure OpenAI 설정이 필요합니다" 로 문구가 바뀌고, 04 는 그대로 스캔본으로 걸린다.

원본을 `<pre>` 로 굽는 것도 이 폴백 때문이다. 프로포셔널 폰트로 조판하면
PDF 추출에서 파이프 표의 열 구분이 뭉개진다.
