# CLAUDE.md — 이음 웹 콘솔 (apps/ieum-web)

이음 관리 콘솔의 React 판이다. 옛 콘솔 `apps/web/ieum`(바닐라 JS)을 메뉴별로 옮기는 중이고, 디자인 가이드(문서 · 린트 · 스킬)를 이 폴더 안에 함께 둔다. 이 파일은 이 폴더에서만 적용된다 — 저장소 전체 규칙은 루트 `CLAUDE.md`.

## 우선 규칙

이 앱의 규칙이 개인 전역 규칙 · 다른 저장소의 관례보다 우선한다.

- **이음이 기준이다.** 모습 · 동작 · 문구 · 반응형은 이음 원본 콘솔에서 정한다. 같은 이름의 스킬을 가진 MCP-Studio 가이드(`design-guide`)는 가이드를 세우고 지키는 방법의 참고일 뿐이다 — 그곳의 값 · 규칙 · 부품 이름을 기본값으로 들이지 않는다. 둘이 부딪히면 이음을 따르고, 이음보다 앞서는 것은 키보드로 닿기 · 포커스 보이기 하한뿐이다(DESIGN `## 접근성`)
- **루트 규칙을 따른다.** 주석 · UI 문구 · 커밋 메시지는 한국어. `window.confirm` · `alert` · `prompt`를 쓰지 않는다 — 확인은 앱 안 Modal(oxlint `no-alert`). 화면에 뜨는 숫자와 문구는 실제 데이터로 뒷받침한다 — 하드코딩한 건수 · 시각 · "방금" 같은 안내를 새로 만들지 않는다(알려진 예외는 `docs/DESIGN.md` `## 이식 기간` 보존 목록). Docker · pnpm · uv를 쓰지 않고, `apps/backend/.env` · `.mcp.json`은 커밋하지 않는다
- **루트 규칙과 다른 점.** Node는 Volta로 고정한 24.15.0이다(`package.json` `volta` · `.nvmrc`). CSS는 `apps/admin`의 한 파일이 아니라 자기 `src/styles/tokens.css` + CSS Modules(Vite 내장)다. 루트 npm workspaces에 넣지 않는다 — 루트 lockfile을 바꾸면 admin 이미지 빌드(`npm ci -w admin`)가 깨질 수 있어 이 폴더에서 따로 설치한다
- **새 의존성을 들이지 않는다.** `apps/admin`이 이미 쓰는 패키지만, 버전은 `package.json`에 적힌 값 그대로(`^` 없음). 버전을 바꾸는 것도 사용자 확인을 거친다. UI 킷 · 상태 라이브러리 · eslint · stylelint · prettier는 없다 — 가이드 강제는 oxlint + 의존성 없는 `lint/` 스크립트가 한다
- **프런트 테스트 파일(`*.test.*` · `*.spec.*`)을 만들지 않는다**(`lint:source`가 막는다). 규칙은 타입 · 린트 · `/_guide` 카탈로그 · ui-review · 브라우저 확인으로 지킨다
- **계획 · 설계 · 감사 · 검증 문서를 저장소에 만들지 않는다.** `docs/`에는 DESIGN · COMPONENTS 둘만 둔다(`lint:docs`가 검사). 화면의 요구 메모는 화면 파일 머리 주석에 쓴다. 작업 산출물은 git에 넣지 않는 개인 작업본에 둔다

## 명령

이 폴더에서 돌린다(자세한 것은 `README.md` `## 명령`).

```bash
npm ci               # 설치 — Volta가 Node 24.15.0으로 맞춘다
npm run dev          # http://localhost:5174/ieum/ — /api/ieum을 IEUM_BACKEND로 넘긴다
npm run typecheck    # tsc
npm run lint         # oxlint · lint:source · lint:tokens · lint:docs
npm run build        # typecheck 뒤 vite build → dist/
```

- 개발 서버는 백엔드를 띄우지 않는다. 백엔드를 먼저 띄우고(루트 `CLAUDE.md` `## 명령`), 주소가 기본값(`vite.config.ts`)과 다르면 `IEUM_BACKEND=http://localhost:<포트> npm run dev`로 지정한다

## 이식 기간

옛 콘솔과 이 앱이 나란히 있는 동안의 메모다. 옛 콘솔을 지우는 전환 때 이 절을 지운다.

- 옛 콘솔은 같은 백엔드가 `/ieum/`에서 서빙한다. 메뉴는 대시보드 + 호출 로그 → 원본 시스템 → 변환 스튜디오 → 테스트 실행 → AI 연결 배포 → 자동 탐색 순서로 하나씩 옮기고, 아직 옮기지 않은 메뉴는 `PendingScreen` 자리다
- 옮길 때 기준은 옛 화면이다 — 모습 · 동작 · 문구 · 호출이 같아야 한다. 옛 화면과 다르게 하는 것은 정해 둔 예외뿐이고 종류는 넷이다 — 항목과 옛 근거(파일:줄)는 `docs/DESIGN.md` `## 이식 기간`
  - **고침** — 접근성 하한(포커스 링 · 모달 닫은 뒤 포커스 복귀 · 키보드로 닿기 · ARIA 보강), 값 · 저장 결함(모르는 상태 값 폴백 · `—ms` · 코드표 저장 등), 가이드 패턴(파괴 동작 확인 모달 · 요청 중 잠금 · 층과 요청의 수명 등)
  - **유지** — 가이드의 일반 관례와 다르지만 이음 그대로 두는 것: 반복 · 등장 모션(흐름 · 깜빡임 · 등장 · 회전 · 맥박)과 파란 띠 위 · 스위치의 흰 포커스 링. 위반이 아니다
  - **허용 차이** — 구현 방식에서 저절로 생기는 차이: 토큰 단계로 묶으며 생긴 값 차이(±1px 류), 토스트 · 모달 본문의 텍스트 렌더, 버튼이 링크로 바뀐 메뉴 이동(LNB 메뉴 · 메뉴로 가는 링크 버튼), 첫 경로 조각이 바뀔 때만 맨 위로 스크롤, 자료 받는 때(처음 필요한 화면이 한 번 받기 · 메뉴에 들어올 때마다 받기 — 액세스 키 포함 · 쓰기 응답이 보는 화면에 바로 반영), 글리프 대신 아이콘, 첫 로딩 비움, 영역 실패 상자, 없는 id 보정, 브라우저 히스토리, 보이지 않는 ARIA 보강
  - **보존** — 서버 사실과 다른 옛 문구 · 출력은 이식 기간 동안 그대로 옮기고 전환 뒤 서버 데이터로 고친다. 루트 규칙 "실제 데이터"의 알려진 예외이고, 새로 만드는 문구 · 숫자에는 넓히지 않는다
- 메뉴마다의 동등성 체크리스트와 예외 행은 이식 작업 지시문이 준다. 그 밖의 차이를 만들게 되면 멈추고 보고한다
- 파일 주인(가이드 쪽 · 화면 쪽 두 작업 흐름의 분담)은 `design-change` 스킬 `## 7`
