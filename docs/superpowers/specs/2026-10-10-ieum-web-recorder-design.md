## 배경

사람이 레거시 웹 화면에서 업무 하나를 수행하면, 그 과정의 화면 조작과 네트워크 호출을 기록해
**다시 실행할 수 있는 업무 기능(Business Function)**으로 바꾸는 기능이다. 업무 기능은 나중에
MCP 도구 하나가 된다.

이전에는 같은 목적의 기능이 두 갈래로 있었다.

- 본체의 Chrome 확장 기록: 사용자의 평소 브라우저에서 트래픽을 관측한다. 쓰기 차단, 화면
  스냅샷, 원격 배포가 어렵다.
- 본체의 LLM 자동 탐색(aa82467): 이음 자동 탐색과 중복이라 `ce9274b`에서 지우고 이음으로 합쳤다.

이음 자동 탐색(`app/ieum/discovery`)은 메뉴를 전부 훑어 **낱개 API 목록**을 만든다. 어떤 API가
어떤 업무에서 어떤 순서로 쓰이는지는 모른다. 레코더는 그 빈자리, 즉 **API를 업무 단위로 묶는 일**을
맡는다.

### 실험으로 확인한 것 (2026-10-09, 버린 코드)

| 질문 | 결과 |
|---|---|
| 우리 가드(Playwright)가 브라우저를 쥐고, 다른 CDP 클라이언트가 조작해도 쓰기를 막을 수 있나 | 된다. Browser Use·Stagehand가 누른 저장 요청을 모두 가로챘다 |
| 쓰기를 가짜 `200 {}`으로 막으면 | 자율 에이전트가 생성 번호를 찾아 헤매 토큰이 4배(7.2만→29.9만)가 됐다. 가짜 응답은 쓰지 않는다 |
| 서버 브라우저 화면을 웹으로 중계하고 영상 위를 클릭하면 무엇을 눌렀는지 알 수 있나 | 12번 모두 정확, 전부 `isTrusted=true`. 좌표 환산(0.75배)도 맞았다 |
| 한글 입력 | IME 조합 후 `Input.insertText`로 "한빛"이 깨지지 않았다 |
| 승인 판단을 버튼 글자로 하면 | "승인대기" 행 클릭이 금지어 "승인"에 걸렸다. 판단은 **나가는 요청**으로 해야 한다 |
| 사용자 둘이 동시에 | 브라우저 세션별로 쿠키·기록이 섞이지 않았다 |
| 지연·프레임 | 같은 PC에서 입력→화면 반영 중앙값 20ms, 프레임 장당 약 39KB |

실험의 시연 사이트는 모든 화면이 XHR(JSON) 방식이었다. 서버가 HTML을 그려 주는 레거시 화면은
실험하지 않았고, 2판에서 설계로 보탰다(4절).

## 목표

1. 사용자가 이음 콘솔 안에서 서버 브라우저를 조작해 업무 하나를 기록한다(화면 중계).
2. 기록을 분석해 업무 기능 정의(단계, 단계 사이 값 연결, 입력값 출처, 정책)를 만든다.
   XHR(JSON) 화면과 서버 렌더링(HTML 표) 화면을 모두 다룬다.
3. 업무 기능을 실제로 다시 실행해 검증한다(Replay).
4. 사람이 검토 화면에서 고치고 확정한다. 단계가 하나인 업무는 이음 도구로 바로 등록한다.

## 비목표

- **여러 단계를 도구 하나로 실행** (실행 엔진·도구 형식·MCP 배포 스냅샷 확장). 다음 작업(C안)이다.
  다만 이번 업무 기능 형식은 C안이 그대로 읽을 수 있게 정한다.
- AI 에이전트가 운전자를 맡는 기록(자연어 목표). 다음 단계에서 새 기록 화면의 "운전자" 자리에 더한다.
- 자동 탐색 결과에서 묶음 후보 추천. 분석기만 공용으로 설계한다.
- 기록 하나를 여러 업무로 나누는 분할 추천. 근거 데이터(ActionSpan, 스냅샷)는 남긴다.
- 이음 콘솔 사용자 로그인과 권한(Keycloak 등). 이음 전체의 별도 작업이다.
- 동시 기록 대기열. 상한을 넘으면 거절하고 안내한다.
- 표가 아닌 HTML 화면에서 값 꺼내기, 여러 페이지에 걸친 목록 모으기.
- 파일 업로드, 드래그, 화면 상태까지 비교하는 검증, 스크린샷 안 개인정보 가리기.
- Git 소스 분석, MCP 빌더 연동(다른 담당).

## 확정한 결정

| 주제 | 결정 | 이유 |
|---|---|---|
| 화면 전달 | **처음부터 화면 중계** (CDP 화면 스트리밍 + 입력 역중계) | 실제 배포가 원격 웹서버·다중 사용자다. 로컬 창으로 먼저 만들면 두 번 만든다 |
| MVP 결과물 | **검증된 업무 기능 정의까지** (B안). 도구 등록은 단건만 | 우리 팀 경계가 "검증된 업무 기능"이다. 실행 엔진 확장은 정의가 확정된 뒤 그 모양에 맞춘다 |
| 로그인 | **자동 로그인, 안 되면 사람이 직접** | 서비스 계정이 있으면 언제든 재검증 가능. OTP·캡차·SSO·권한 부족이면 사람이 중계 화면에서 로그인 |
| 쓰기 | 운영은 **요청을 붙잡고 승인**, 스테이징은 통과. 가짜 응답 금지. **어느 시스템으로 가는 쓰기든** 같다 | 실험 결과. 판단 기준은 버튼 글자가 아니라 나가는 요청. 결재 시스템처럼 다른 시스템의 저장도 운영 데이터를 바꾼다 |
| 메뉴 | 새 메뉴 **"업무 기록"** | 업무 기능은 계속 쌓이고 다시 검증하는 자산이다. 운전자(사람/AI)와 무관하게 한 곳에 모인다 |
| 기록 중 화면 | 영상 왼쪽 크게 + 오른쪽 타임라인 | 업무를 하며 무엇이 잡히는지 바로 보인다 |
| 동시 기록 상한 (2판) | **서버 전체 + 사람당, 둘 다 설정값.** 기본 서버 4, 사람당 1. 넘으면 거절하고 누가 몇 개 쓰는지 보여 줌 | Chromium 하나가 메모리를 수백 MB 쓴다. 사람당 상한이 없으면 한 사람이 다 쥐거나 잊고 둔 탭이 자리를 막는다 |
| 스크린샷 (2판) | **확정할 때까지만 보관.** 확정하면 지우고, 확정하지 않은 기록은 7일 뒤 지운다(설정값) | 그림 속 개인정보는 가리기 어렵다. 그림이 꼭 필요한 순간은 사람이 검토할 때뿐이다 |
| 서버 렌더링 HTML (2판) | **HTML 안의 표를 행 데이터(JSON)로 바꿔 JSON 응답처럼 다룬다** | 레거시 대부분이 이 방식이다. 바꾸는 부품 하나만 더하면 분석·검증 설계를 그대로 쓴다 |
| 이동 범위 (2판) | **막지 않고 기록한다.** 서버 자신·클라우드 메타데이터·브라우저 내부 주소만 항상 차단 | 대상 주소는 울타리가 아니라 기준점이다. 중계 화면에 주소창이 없어 사람은 대상 화면의 링크로만 이동한다 |

## 1. 전체 구조

```
[이음 콘솔 웹 화면]  업무 기록 메뉴
   │  REST: 기록 시작·종료·목록·검증·확정·등록
   │  WebSocket: 화면 영상 ↓ / 클릭·키 입력 ↑ / 승인 요청 ↕
   ▼
[이음 백엔드 (콘솔 프로세스, uvicorn 이벤트 루프)]
   ├─ recorder/session.py    기록 세션 = 사용자 한 명의 브라우저. 수명·상한·회수
   ├─ recorder/manager.py    세션 생성·조회·상한(서버·사람당)·유휴 회수·Playwright 수명
   ├─ recorder/relay.py      CDP 화면 스트리밍(최신 프레임만), 입력 역중계, 좌표 환산, 한글
   ├─ recorder/guard.py      쓰기 붙잡기·승인, 항상 차단 목록, 로그인 요청 통과
   ├─ recorder/trace.py      ActionSpan 기록 (행동 + 직전/직후 ARIA 스냅샷 + 네트워크)
   ├─ recorder/htmltable.py  HTML 응답 → 표·이름값 JSON (서버 렌더링 화면용)
   ├─ recorder/analyze.py    기록 → 업무 기능 (역할 판별, 값 연결, 입력값 출처, 정책, 설명 초안)
   ├─ recorder/replay.py     Replay 검증
   ├─ recorder/retention.py  스크린샷·오래된 기록 정리
   └─ discovery/capture.py   크롤러와 공용인 네트워크 판정 함수
   ▼
[Chromium]  기록 세션마다 하나 (화면 없음)
```

### 공용 판정 함수

크롤러의 네트워크 판정(쓰기 여부, 보존 헤더, 표본 상한, 로그인 레시피)을 `discovery/capture.py`의
**Playwright를 부르지 않는 함수**로 뗀다. 크롤러는 동기, 레코더는 비동기 Playwright라
`route.continue_()`·`response.text()`를 부르는 방식이 달라서, 판정만 공유하고 호출은 각자 한다.

"기록할 응답인가"는 공유하지 않는다. 크롤러는 화면 이동(document) 응답을 버리지만, 레코더는
서버 렌더링 화면 때문에 document 응답도 기록해야 한다(4절).

### 브라우저 실행 위치

**콘솔 프로세스의 uvicorn 이벤트 루프**에서 Playwright 비동기 API로 모든 기록 세션을 돌린다.
기록 세션마다 Chromium을 따로 띄워 사용자 사이를 브라우저 프로세스 단위로 격리한다.

- WebSocket과 CDP가 같은 루프에 있어 스레드 사이 중계가 없다.
- **이 루프를 막는 일은 하지 않는다.** 파일 쓰기, 분석, HTML 변환, 동기 HTTP는 `asyncio.to_thread`로
  넘긴다. 루프가 막히면 모든 사용자의 화면 중계가 멈춘다.
- 브라우저는 기존 `discovery/browser.py` 순서(번들 Chromium → Chrome → Edge)로 찾는다.
- 사용자가 많아지면 세션별 프로세스로 옮길 수 있게 `session.py` 경계를 분명히 둔다.

### 격리의 범위

이음 콘솔에는 사용자 로그인이 없다(상단 사용자 이름은 `data/sources/workspace.json`의 고정값).
MVP의 격리는 **기록 세션 단위**다. 세션마다 브라우저가 따로이고, 세션 화면은 그 세션의 접속 토큰으로만
열린다. 기록자는 시작할 때 입력한 이름으로 남기고, 사람당 상한도 이 이름으로 센다. 콘솔 로그인이 생기면
계정으로 바꾼다.

## 2. 이동 범위와 항상 차단 (2판)

대상 시스템 주소는 **기준점**이다. 브라우저가 처음 열 화면, 분석에서 업무 API와 외부 잡음을 가르는 기준,
Replay의 기준 주소, 도구를 둘 원본 시스템을 정한다. 사람이 기록하는 동안 대상 밖으로 이동하는 것은 막지 않는다.

| 경우 | 처리 |
|---|---|
| 대상 밖 화면 이동(링크, 팝업, SSO 리다이렉트) | 막지 않는다. 기록하고 그 단계의 출처를 따로 남긴다 |
| 대상 화면 스크립트가 다른 주소로 보내는 데이터 요청 | 막지 않는다. 기록하고 "다른 출처"로 표시한다(분석 참고용) |
| 정적 자원(이미지·글꼴·스크립트) | 막지 않는다 |
| **항상 차단** | 서버 자신(`localhost`, `127.0.0.1`, `::1`, 콘솔 포트), 클라우드 메타데이터(`169.254.169.254`), `file://`·`chrome://`·`devtools://` 같은 브라우저 내부 주소, `IEUM_RECORDER_DENY` 목록 |

항상 차단은 어떤 업무에서도 정당하게 갈 일이 없는 곳이다. 대상 시스템이 실수로든 악의로든 이런 곳을 부르게
해도 서버 내부가 드러나지 않게 한다. 막은 요청은 타임라인에 "차단(서버 보호)"으로 남긴다.

**전제: 중계 화면에 주소창이 없다.** 사람은 대상 화면이 제공하는 링크와 팝업으로만 이동한다. 나중에
주소창을 넣으면 사람이 서버 브라우저로 임의 내부 주소를 열 수 있게 되므로 이 판단을 다시 해야 한다.

## 3. 데이터 모델

세 층이다. 기록(Recording) → 행동 묶음(ActionSpan) → 업무 기능(BusinessFunction).

### 기록 (Recording)

```json
{
  "id": "rec_8f2a1c", "name": "9월 발주 상세 조회", "owner": "홍길동",
  "sourceBase": "http://10.20.4.30:8080/po", "start": "/login.do", "env": "op", "readPost": "",
  "login": { "mode": "auto", "recipe": { "loginRel": "/login.do", "actionRel": "/loginProc.do",
             "userField": "userId", "passField": "userPw", "extra": {}, "json": false }, "path": "/po/loginProc.do" },
  "status": "recording",
  "startedAt": 1791600000, "endedAt": null, "spanCount": 0,
  "approvals": [ { "id": "a1b2", "method": "POST", "url": "/poSave.do", "label": "저장", "decision": "approve", "at": 1791600120 } ],
  "functionId": null, "error": null
}
```

- `env`: `op`(운영) | `stg`(스테이징)
- `login.mode`: `auto`(서비스 계정, 비밀번호는 금고) | `manual`(사람이 직접, 비밀번호 저장 안 함)
- `recipe`는 필드 이름만 남긴다. 계정 값을 알면 로그인 요청에서, 모르면 로그인 화면 HTML에서 읽는다.
- `status`: `recording` → `analyzing` → `verifying` → `review` → `confirmed`, 또는 `failed` / `interrupted`
- `approvals`: 쓰기 승인·거절·시간 초과·스테이징 통과 이력. 항상 차단한 요청도 `decision: "denied-host"`로 남긴다.

**행동 묶음은 기록 요약과 따로 저장한다(2판).** 기록 요약은 스토어 하나(`recorder.recordings`)에 두고,
행동 묶음은 기록마다 파일 하나(`data/ieum/recorder/<기록 id>/spans.jsonl`)에 **한 줄씩 덧붙인다.**
1판은 모든 기록의 행동 묶음을 JSON 파일 하나에 넣고 묶음마다 파일 전체를 다시 썼는데, 기록이 쌓일수록
느려지고 그 쓰기가 이벤트 루프를 막아 다른 사용자의 화면 중계까지 끊는다.

### 행동 묶음 (ActionSpan)

```json
{
  "seq": 5,
  "action": { "type": "click", "target": { "tag": "BUTTON", "role": "button", "name": "", "text": "조회", "id": "btnSearch" },
              "isTrusted": true, "t": 1791600050 },
  "fills": [ { "target": { "id": "fromDt", "label": "발주일" }, "value": "20260901" } ],
  "pre":  { "url": "/poListView.do", "title": "발주 현황", "aria": "<마스킹한 ARIA 스냅샷>", "shot": "5-pre.jpg" },
  "network": [
    { "method": "GET", "url": "<마스킹한 URL>", "path": "/po/poList.do", "origin": "http://10.20.4.30:8080",
      "status": 200, "ctype": "application/json;charset=UTF-8", "charset": "UTF-8", "rtype": "xhr",
      "headers": { "x-requested-with": "XMLHttpRequest" }, "post": null,
      "res": "<마스킹한 응답 표본>", "data": null, "file": false,
      "held": false, "decision": "", "primary": true, "t": 1791600050.4 }
  ],
  "post": { "url": "/poListView.do", "title": "발주 현황", "aria": "<마스킹한 ARIA 스냅샷>", "shot": "5-post.jpg" }
}
```

- `action.type`: `click` | `key` | `navigate`. 입력란에 넣은 값은 `fills`에 모은다(페이지 안 `change` 이벤트).
- 행동이 끝나고 네트워크와 화면이 잠잠해지면 묶음을 닫는다. 그사이 나간 요청이 그 행동에 속한다.
- `network`에는 XHR·fetch와 **화면 이동(document) 응답도** 담는다. document 응답은 서버 렌더링 화면의 결과다.
- `data`: 응답이 HTML이면 표·이름값을 바꾼 JSON(4절). JSON 응답이면 `null`(필요할 때 `res`를 파싱한다).
- `primary`: 대상 시스템 출처의 요청인가. 다른 출처 요청도 기록한다(2절).
- `charset`: 요청·응답의 문자 인코딩. Replay가 폼을 같은 인코딩으로 보낸다(EUC-KR 레거시).
- **ARIA 스냅샷은 모든 프레임을 뜬다(2판).** 레거시는 iframe·frameset이 많아 `body` 하나만 뜨면 결과가 그려진
  프레임을 놓친다. 프레임마다 뜬 것을 이어 붙인다.
- 저장하는 값은 모두 마스킹한 값이다(5절).

### 업무 기능 (BusinessFunction)

```json
{
  "id": "bf_8f2a1c", "name": "9월 발주 상세 조회", "desc": "발주일 범위로 발주를 조회하고, 목록에서 고른 발주의 거래처와 금액을 확인합니다.",
  "source": { "base": "http://10.20.4.30:8080/po", "recordingId": "rec_8f2a1c", "made": "manual-record", "env": "op" },
  "inputs": [
    { "name": "fromDt", "type": "date", "source": "USER_INPUT", "ex": "20260901", "screenLabel": "발주일(시작)",
      "confidence": "high", "required": true, "needsValue": false }
  ],
  "steps": [
    { "id": "s1", "role": "core", "origin": "http://10.20.4.30:8080", "method": "POST", "path": "/poSearch.do",
      "charset": "EUC-KR", "kind": "html", "exec": "http",
      "params": [ { "a": "fromDt", "loc": "form", "from": "input.fromDt", "source": "USER_INPUT", "ex": "20260901" } ],
      "headers": {}, "outputs": { "poNo": "$.tables[0].rows[0].발주번호" },
      "recordedStatus": 200, "recordedRes": "<마스킹한 표본 또는 HTML 변환 JSON>" },
    { "id": "s2", "role": "core", "origin": "http://10.20.4.30:8080", "method": "GET", "path": "/poDetail.do",
      "charset": "EUC-KR", "kind": "html", "exec": "http",
      "params": [ { "a": "poNo", "loc": "query", "from": "s1.poNo", "source": "PREVIOUS_STEP_OUTPUT", "ex": "PO-2609-0142" } ] }
  ],
  "references": [ { "method": "GET", "path": "/common/codeList.do", "role": "code" } ],
  "excluded": [ { "method": "GET", "path": "/chart/monthly.do", "role": "noise", "why": "행동 없이 화면이 스스로 부른 요청" } ],
  "output": { "from": "s2", "fields": ["$.fields.거래처", "$.fields.발주금액"] },
  "auth": { "mode": "session", "recipe": { "...": "..." } },
  "executionMode": "session",
  "policy": { "operation": "READ", "risk": "LOW", "approval": "NONE", "envPolicy": "op-auto", "sensitivity": null, "scope": null },
  "verification": { "status": "verified", "at": 1791600300,
                    "runs": [ { "kind": "same-values", "ok": true }, { "kind": "varied-values", "ok": true } ] },
  "evidence": { "s1": [5], "s2": [6] },
  "status": "draft", "policyIncomplete": true, "notes": []
}
```

설계 원칙:

1. **단계의 요청 형식은 지금 이음 도구의 파라미터 형식(`a`, `loc` 등, `gateway/spec.py`)을 따르고
   `from`(값의 출처)만 더한다.** C안의 실행 엔진은 단계마다 기존 `engine.build_request`를 부르고
   단계 사이에 값만 넘기면 된다.
2. **단계마다 자기 출처(`origin`)를 들고 있다(2판).** 결재 시스템 팝업처럼 여러 시스템을 오가는 업무는
   단계마다 출처가 다르다. Replay는 단계의 출처로 부르고, 도구 등록은 출처별 원본 시스템 아래에 둔다.
3. **`kind`**: `json` | `html` | `other`. `html`이면 값 꺼내기와 구조 비교를 HTML 변환 JSON으로 한다.
4. **`exec`**: `http` | `browser`. 매번 바뀌는 숨은 토큰이 필요한 폼은 `browser`다(4절).
5. **입력값 출처 6종**: `USER_INPUT`, `PREVIOUS_STEP_OUTPUT`, `SESSION_CONTEXT`, `SYSTEM_CONFIG`,
   `DERIVED`, `CONSTANT`. `from`은 `input.<이름>` | `<단계 id>.<출력 이름>` | `session.<키>` |
   `config.<키>` | `const:<값>` 중 하나다.
6. **`needsValue`(2판)**: 기록한 값이 마스킹되어 원값을 알 수 없는 입력(예: 전화번호로 검색)이다.
   기록 세션이 끝난 뒤 다시 검증하려면 검토 화면에서 값을 넣어야 한다(5절).
7. **`desc`는 비워 두지 않는다(2판).** MCP 도구 설명의 품질이 AI가 도구를 고르는 정확도를 좌우한다. 분석이
   화면 제목·입력 라벨·출력 열 이름으로 초안을 만들고 사람이 검토 화면에서 다듬는다.
8. **정책 중 자동으로 채우는 것**: 작업 유형, 위험도, 승인 방식. 권한 범위와 민감도는 사람이 채운다.
   비어 있으면 `policyIncomplete`로 목록에 "정책 미완"을 표시한다.
9. **`evidence`**는 단계가 나온 ActionSpan 번호다.

### 저장 위치

| 대상 | 위치 |
|---|---|
| 기록 요약 | JSON 스토어 `recorder.recordings` |
| 행동 묶음 | `data/ieum/recorder/<기록 id>/spans.jsonl` (한 줄씩 덧붙임) |
| 업무 기능 | JSON 스토어 `recorder.functions` |
| 스크린샷 | `data/ieum/recorder/<기록 id>/<seq>-pre.jpg`, `<seq>-post.jpg` (보관 규칙은 5절) |
| 서비스 계정 비밀번호 | 금고 `rec:<기록 id>` (등록 때 원본 시스템 키로 옮긴다) |

스토어의 읽고-고쳐-쓰기 구간은 `with store.LOCK:`으로 감싸고, 이벤트 루프에서는 `asyncio.to_thread`로 부른다.

## 4. 서버 렌더링 화면 (2판)

JSP 같은 레거시는 조회 버튼이 폼을 제출하면 서버가 결과 표까지 그린 **HTML 페이지 전체**를 돌려준다.
JSON이 아니라서 값 꺼내기, 구조 비교, AI에게 줄 결과가 모두 막힌다. 그래서 HTML 응답 안의 표를
데이터로 바꾼 **JSON 사본**을 만들어 JSON 응답처럼 다룬다(`htmltable.py`).

```json
{
  "tables": [
    { "columns": ["발주번호", "거래처", "금액"],
      "rows": [ { "발주번호": "PO-2609-0142", "거래처": "한빛상사", "금액": "4,850,000",
                  "_links": ["poDetail.do?poNo=PO-2609-0142"] } ] }
  ],
  "fields": { "거래처": "한빛상사" },
  "hidden": { "_csrf": "a8f3…" }
}
```

바꾸는 규칙:

- **열 이름**: `<th>` 글자. 같은 이름이 또 나오면 `금액_2`처럼 번호를 붙인다. 머리글이 여러 단이면 마지막 단을 쓴다.
- **행**: `<td>` 글자를 열에 맞춘다. `rowspan`·`colspan`은 병합 칸을 각 칸에 같은 값으로 채운다.
- **`_links`**: 칸 안의 링크 주소와 `onclick="openDetail('PO-…')"` 안의 문자열 값. 레거시에서 다음 화면으로
  넘어가는 값이 주로 여기 있다.
- **`fields`**: 표가 아니라 `<th>이름</th><td>값</td>`이나 `<label>`·입력란으로 짝지어진 상세 화면의 "이름: 값".
- **`hidden`**: 폼의 숨은 입력란. 매번 바뀌는 토큰을 찾는 데 쓴다.
- **버리는 것**: 머리글이 없는 표, 칸이 하나뿐인 표(화면 배치용).
- HTML 변환은 CPU를 쓰므로 `asyncio.to_thread`로 돌린다. 본문은 기존 상한(40KB)까지만 읽는다.

변환 뒤에는 6절의 분석이 그대로 동작한다.

- 핵심 판정: 사본의 값이 직후 화면(ARIA)에 보였는가.
- 값 연결: 다음 요청의 값이 사본 어디에 있는가(`$.tables[0].rows[0].발주번호`, `$.tables[0].rows[0]._links[0]`에서
  쿼리 값 추출 포함).
- 구조 비교: 표의 열 이름 집합과 `fields` 키 집합.
- 출력: 마지막 화면에 보인 `rows`·`fields`의 필드.

**매번 바뀌는 숨은 값.** 폼의 CSRF 토큰, ASP.NET `__VIEWSTATE`·`__EVENTVALIDATION`처럼 화면을 열 때마다
새로 받는 값을 기록 때 값으로 다시 보내면 서버가 거절한다. 분석이 "이 파라미터 값은 직전 화면 HTML의
`hidden`에 있었다"를 찾으면 `SESSION_CONTEXT`로 분류하고 그 단계를 `exec: "browser"`로 둔다. Replay는
브라우저 안에서 직전 화면을 열고 폼을 채워 제출한다.

**한계.** 표가 아닌 화면(`<div>`·`<ul>` 나열, 카드형)은 값을 꺼내지 못한다. 기록과 "200이고 로그인 화면이
아님"까지만 검증하고, 검토 화면에 "표가 없어 값을 꺼낼 수 없습니다"를 표시한다. 여러 페이지에 걸친 목록은
기록한 그 페이지만 다룬다.

## 5. 개인정보 (2판)

| 대상 | 규칙 |
|---|---|
| 응답 표본·요청 값·URL | 저장 전에 `discovery.masking.Masker`로 가린다. 마스킹하지 못하면 저장하지 않는다 |
| ARIA 스냅샷 | **같은 마스킹기로 가린 뒤 저장한다.** 응답과 화면을 같은 규칙으로 가리므로 "응답 값이 화면에 나타났나" 판정은 그대로 된다 |
| 스크린샷 | **업무 기능을 확정하면 지운다.** 확정하지 않은 기록은 `IEUM_RECORDER_SHOT_DAYS`(기본 7일) 뒤 지운다. 확정 뒤 검토 화면의 근거는 마스킹된 ARIA 텍스트로 보여 준다 |
| 실시간 화면 영상 | 저장하지 않는다. 보내고 버린다 |
| 비밀번호 입력란 | `change` 이벤트를 기록하지 않는다. 로그인 요청 본문의 비밀번호는 마스킹기가 숨긴다 |
| **입력 원값** | 기록 세션 메모리에만 둔다. 저장하는 값은 마스킹한 값이다 |

**입력 원값과 Replay.** 사용자가 전화번호로 검색했다면 저장되는 값은 `010****1234`다. 이 값으로 다시
부르면 검증이 실패한다. 그래서:

- 기록 직후의 Replay(세션이 살아 있을 때)는 **메모리의 원값**으로 부른다.
- 세션이 끝난 뒤 다시 검증할 때 마스킹된 입력은 `needsValue: true`로 표시하고, 검토 화면에서 사람이 값을 넣어야
  검증한다. 넣은 값도 저장하지 않는다.

스크린샷과 기록 정리는 `retention.py`가 서버 기동 때와 하루 한 번 돈다.

## 6. 분석 (기록 → 업무 기능)

규칙만으로 동작하고 LLM에 의존하지 않는다. LLM은 이름·설명을 다듬는 선택 기능이다.

1. **잡음 걸러내기**: 정적 파일, 행동 없이 반복되는 요청(폴링), 로그인·로그아웃(로그인은 `auth`로 따로 둔다),
   항상 차단한 요청, 승인하지 않아 보내지 않은 쓰기. 다른 출처 요청은 버리지 않고 후보로 둔다(결재 시스템 등).
   다만 접속 통계·광고처럼 응답이 화면에 나타나지 않는 다른 출처 요청은 2단계에서 자연히 빠진다.
2. **HTML 변환**: document 응답과 HTML 조각 응답은 4절대로 JSON 사본을 만든다.
3. **역할 붙이기**

   | 역할 | 근거 |
   |---|---|
   | `core` | 행동 직후 나갔고, 응답(또는 HTML 사본) 값이 직후 ARIA 스냅샷에 나타난다. 또는 사람이 승인·스테이징으로 보낸 쓰기 |
   | `prereq` | 응답 값이 뒤 단계 요청에 쓰인다 |
   | `code` | 코드표 형태 응답 (`infer.detect_code_tables`) |
   | `page` | 값이 화면에 나타나지 않은 화면 이동 |
   | `noise` | 1단계에서 걸러진 것 |

4. **같은 API 묶기**: 값만 다른 경로는 `{id}`로 묶는다. **경로는 같고 파라미터로 기능이 갈리는 API는 나눈다(2판).**
   `cmd`, `action`, `method`, `mode`, `op`, `service`, `operationName`(GraphQL) 같은 구분 파라미터 값을 묶음 기준에
   넣는다. `*.do?cmd=list`와 `*.do?cmd=save`가 하나로 합쳐지면 안 된다.
5. **값 연결과 입력값 출처 분류** (공용 분석기의 핵심). 파라미터 값을 이 순서로 대조한다.

   | 순서 | 대조 대상 | 결과 |
   |---|---|---|
   | 1 | 사용자가 입력·선택한 값 (`fills`) | `USER_INPUT` + 화면 라벨 |
   | 2 | 앞 단계 응답(또는 HTML 사본, `_links` 안 쿼리 값) | `PREVIOUS_STEP_OUTPUT` + 경로 |
   | 3 | 직전 화면 HTML의 숨은 입력란 | `SESSION_CONTEXT`, 그 단계는 `exec: "browser"` |
   | 4 | 로그인 정보·세션 응답·쿠키 | `SESSION_CONTEXT` |
   | 5 | 여러 API 공통 값 | `SYSTEM_CONFIG` |
   | 6 | 날짜 계산처럼 보이는 값 | `DERIVED` (확신도 낮음) |
   | 7 | 어디에도 안 맞고 늘 같은 값 | `CONSTANT`. 단 날짜·번호처럼 보이면 확신도 낮음(2판) |

   같은 값이 여러 곳에 있으면 확신도를 낮게 매겨 검토 화면에서 묻는다. 날짜 선택기처럼 `change` 이벤트 없이
   스크립트가 값을 넣으면 1번에 안 걸려 `CONSTANT`가 되므로, 날짜·번호 모양의 고정값은 "확인 필요"로 둔다.
6. **단계 확정과 출력**: `core`와 `prereq`가 단계가 된다. 출력은 마지막 핵심 단계 응답 중 사용자가 마지막
   화면에서 본 필드다.
7. **정책 추정**: 단계 중 가장 위험한 것을 업무 기능의 정책으로 쓴다.

   | 근거 | 작업 유형 | 위험도 | 승인 |
   |---|---|---|---|
   | 모두 GET, 승인 이력 없음 | READ | LOW | NONE |
   | 쓰기 + 저장·등록 | CREATE | MEDIUM | CONFIRM |
   | 쓰기 + 수정·변경 | UPDATE | MEDIUM | CONFIRM |
   | 쓰기 + 삭제 | DELETE | HIGH | HITL |
   | 쓰기 + 승인·결재·결제·이체 | APPROVE | CRITICAL | HITL |

8. **설명 초안(2판)**: "<화면 제목>에서 <입력 라벨들>로 <출력 열 이름들>을 조회합니다" 형태로 만든다.

재사용: `masking.Masker`, `infer.py`, `merge`의 경로 정규화.

## 7. Replay 검증

기록 종료 직후 자동으로 시작한다. 기록 브라우저는 검증이 끝날 때까지 닫지 않는다.

### 두 번 실행

1. **같은 값 재실행**: 기록 때 입력값으로 전 단계를 실행한다. 세션이 살아 있으면 메모리의 **원값**을 쓴다(5절).
2. **다른 값 재실행**: `USER_INPUT`만 바꾼다. 값은 기록 안에서 고른다(목록 응답의 다른 번호, select의
   다른 옵션, 날짜 범위는 한 달 앞으로). 고를 값이 없으면 건너뛰고 "같은 값으로만 검증됨"으로 표시한다.

### 실행 방식

| `exec` | 방식 |
|---|---|
| `http` | 기록 세션 쿠키 + 보존 헤더(User-Agent, Referer, X-Requested-With)로 서버가 직접 호출. 단계의 `origin`으로 보내고, 폼은 단계의 `charset`으로 인코딩한다 |
| `browser` | 기록 세션 페이지에서 직전 화면을 열고 폼을 채워 제출하거나 `fetch()`로 보낸다. 숨은 토큰이 필요한 단계 |

`http`로 실패하고 원인이 브라우저 의존(토큰·서명)으로 보이면 `browser`로 다시 시도한다. 성공한 방식을
`executionMode`로 남긴다(`direct` | `session` | `browser`).

### 성공 판정

한 단계가 성공이려면 모두 만족해야 한다.

1. 2xx이고 로그인 화면으로 돌려보내지지 않았다(`session_auth.expired` 재사용).
2. 응답(또는 HTML 사본)의 구조가 기록 때와 대부분 같다. JSON은 키 이름, HTML은 표 열 이름과 `fields` 키.
   표도 JSON도 아니면 구조 비교를 건너뛴다.
3. 오류 표시가 없다(`resultCode`·`RSLT` 실패값, "권한이 없습니다" 같은 문구).
4. 다음 단계로 넘길 값을 실제로 꺼낼 수 있다.

### 실패 이유 코드

`auth_expired`, `waf_blocked`, `http_error`, `shape_mismatch`, `error_response`, `chain_broken`,
`write_denied`, `needs_value`(원값이 필요한 입력), `browser_only`(실패 아님, 실행 방식 정보)

### 쓰기 단계

- 운영: 그 단계 직전에 다시 승인을 받는다. 거절하면 그 단계부터 실행하지 않고 `write_denied`.
- 스테이징: 승인 없이 실행한다.
- 쓰기 단계는 같은 값 재실행만 한다.
- 기록 세션이 끝난 뒤의 재검증에서는 운영 쓰기를 보내지 않는다(물을 승인 창이 없다).

### 세션이 끊겼을 때

- `login.mode = auto`: 금고 계정으로 다시 로그인해 이어 간다(`session_auth`). 다만 `exec: "browser"` 단계는
  브라우저가 없으므로 검증하지 않고 이유를 남긴다.
- `login.mode = manual`: 기록 세션이 살아 있는 동안만 검증한다. 끊기면 "다시 로그인 필요"로 남긴다.

### 안전장치

- 단계의 출처로만 보내고, 항상 차단 목록(2절)으로는 보내지 않는다.
- 운영 주소면 요청 간격 최소 0.6초(이음 탐색 정책과 같은 기준).
- 응답은 마스킹한 뒤 저장한다. 모든 Replay 요청을 감사 이력에 남긴다.

재사용: `gateway/session_auth.py`, `gateway/engine.parse_body`, `discovery/verify.py`의 판정 규칙.

## 8. 쓰기 처리 (기록 중)

| 환경 | 쓰기 요청(POST·PUT·PATCH·DELETE, 이름이 쓰기 같은 XHR GET)이 나갈 때 |
|---|---|
| 운영 | 가드가 요청을 붙잡고 콘솔에 승인 창을 띄운다. 승인하면 보내고, 거절하면 버린다. 가짜 응답은 쓰지 않는다 |
| 스테이징 | 그대로 보내고 기록에 쓰기라고 표시한다 |

- **어느 출처로 가는 쓰기든** 같은 규칙이다(결재 시스템의 저장도 운영 데이터를 바꾼다).
- 판단 기준은 **나가는 요청**이다. 버튼 글자는 승인 창의 설명으로만 쓴다.
- 승인 창이 떠 있는 동안 다른 입력을 막는다. 2분 안에 답이 없으면 보내지 않는다.
- **로그인 요청은 비밀번호 계열 필드(`pw`, `pwd`, `pass`, `passwd`, `password`)가 있을 때만** 로그인으로 보고
  승인 없이 통과시킨다. `token` 같은 이름으로 판단하면 `csrfToken`이 든 저장 요청을 로그인으로 오인한다.
- 사용자가 지정한 조회용 POST(`readPost`)는 승인 없이 통과한다.
- 승인·거절 이력을 기록에 남긴다(감사, 정책 추정 근거).
- 자동 탐색의 쓰기 차단 규칙(가짜 응답으로 막기)은 바꾸지 않는다. 레코더만 다른 규칙을 쓴다.

## 9. 화면 (이음 콘솔 "업무 기록" 메뉴)

### 흐름

① 업무 기능 목록 → ② 새 기록 시작 → ③ 기록 중 → (자동 분석·검증) → ④ 검토·검증 → 확정 → ① 목록

- 목록 항목을 누르면 ④가 열린다. 기록 중인 항목은 ③으로 다시 들어간다(같은 탭에서만, 토큰 때문).
- 원본 시스템 연결 마법사에는 "업무 기록으로 시작" 버튼만 두어 이 메뉴로 보낸다.

### ① 업무 기능 목록
업무 기능과 기록 중 항목. 상태(기록 중 / 검증됨 / 부분 검증 / 다시 검증 필요 / 정책 미완 / 실패 / 중단됨),
작업 유형, 단계 수, 응답 방식(JSON·HTML). 위에 지금 쓰는 동시 기록 수(서버 전체, 내 것)를 보여 준다.

### ② 새 기록 시작
업무 이름, 대상 시스템 주소, 시작 화면, 환경(운영/스테이징), 서비스 계정(선택), 조회용 POST 경로(선택),
**기록하는 사람(필수, 사람당 상한 기준)**. 상한에 걸리면 "지금 서버에서 n개, 홍길동 님이 1개 기록 중입니다"를
보여 준다. 다음 단계에서 이 화면에 "운전자(사람/AI)" 선택을 더한다.

### ③ 기록 중
- 왼쪽에 서버 브라우저 영상(화면 폭에 맞춰 축소, 좌표 환산), 오른쪽에 타임라인 패널.
- 위 띠: 기록 시간, 업무 이름, **환경(운영은 붉게)**, 일시정지, 기록 종료, 열린 탭 목록.
- 타임라인: 행동 → 요청, 요청·쓰기·다른 출처·차단 개수. 항목을 누르면 직전·직후 캡처와 요청 내용.
- 쓰기 승인 창: 영상 위에 뜨고 다른 입력을 막는다.
- 일시정지: 업무와 무관한 조작 동안 기록을 멈춘다(브라우저는 계속 쓸 수 있다).
- 대상 사이트의 `alert`·`confirm`은 콘솔에 같은 내용의 창으로 띄워 사용자가 답한다.
- 안내 띠: 자동 로그인 실패, 세션 만료(로그인 화면으로 튕김), 파일 업로드 미지원, 연결 끊김, 기록 상한.

### ④ 검토·검증
- 왼쪽: 설명(초안, 고칠 수 있음), 입력값 표(이름, 화면 라벨, 출처, 기록 값, ⚠ 확인 필요, **값 다시 입력 필요**),
  단계 흐름 카드(출처, JSON/HTML, http/browser, 값 연결, 근거 캡처 또는 확정 뒤에는 ARIA 텍스트),
  단계에 넣지 않은 요청(역할별, 단계로 올리기).
- 오른쪽: 검증 결과(두 번 실행, 실행 방식, 실패 이유), 정책(자동 추정 + 사람 입력 ⚠), 이음 도구 등록.
- 2단계 이상이면 "도구 하나로는 다음 작업에서 지원"으로 안내하고, 단계를 낱개 도구로 등록하는 버튼만 둔다.
- ⚠ 칸이 비어 있어도 확정할 수 있다. 목록에 "정책 미완"으로 표시한다. 확정하면 스크린샷을 지운다고 알린다.

### 콘솔 구현 규칙

- 메뉴 추가: `state.js`의 `VIEWS`, `js/menu/recorder.js`, `index.html`, `main.js`의 `VFN`.
- classic script라 전역 이름이 충돌하면 파일이 통째로 실행되지 않는다. 새 전역 이름은 먼저 grep한다.
- `window.confirm`·`alert`·`prompt`를 쓰지 않는다. 승인 창은 화면 안 창이다.
- 콘솔에 처음으로 WebSocket이 들어온다. 접속 토큰은 세션 시작 응답으로 받고 탭의 `sessionStorage`에만 둔다.

## 10. 오류 처리

원칙: **기록은 잃지 않는다**(행동 묶음을 닫을 때마다 파일에 덧붙인다). **애매하면 안전한 쪽**(마스킹 실패 시
원문 저장 안 함, 승인 응답 없으면 보내지 않음). **루프를 막지 않는다**(무거운 일은 스레드로).

| 상황 | 처리 |
|---|---|
| 브라우저를 띄우지 못함 | 기존 탐색 순서를 따르고, 모두 실패하면 설치 안내 |
| 서버 전체·사람당 상한 초과 | 시작하지 않고 거절. 지금 몇 개가 누구 것인지 보여 줌 |
| 사용자가 탭을 닫음·네트워크 끊김 | 세션 유지(10분). 같은 탭에서 다시 열면 영상과 기록이 이어진다 |
| 사용자 네트워크가 느림 (2판) | 프레임을 쌓지 않고 **최신 프레임만** 보낸다. 밀린 프레임은 버린다 |
| **Chromium이 죽음 (2판)** | 브라우저 연결 끊김을 받아 기록을 `interrupted`로 바꾸고 알린다. 저장된 행동 묶음은 남는다 |
| 10분 동안 입력 없음 | 브라우저 회수, 기록은 `interrupted`. 저장된 행동 묶음으로 분석 가능 |
| 서버 재시작 | 진행 중이던 기록은 `interrupted` |
| 자동 로그인 실패 | 중계 화면을 사용자에게 넘겨 직접 로그인 |
| 기록 중 세션 끊김 | 안내 띠에 "세션 만료" 표시, 다시 로그인 요청. 기록은 이어진다 |
| 쓰기 승인 응답 없음(2분) | 보내지 않음으로 처리하고 알림 |
| 항상 차단 주소 요청 (2판) | 막고 타임라인에 "차단(서버 보호)" |
| 대상 사이트 `alert`·`confirm` | 콘솔 창으로 사용자에게 묻고 답을 전달(자동 탐색처럼 항상 취소하지 않음) |
| 새 창·팝업 | 탭 목록에 추가하고 영상을 새 탭으로 전환. 기록은 모든 탭에서 계속 |
| 파일 다운로드 | "파일 응답"으로 기록, 파일은 저장하지 않음 |
| 파일 업로드 | MVP 미지원. 안내 띠 |
| 핵심 요청을 못 찾음 | 빈 단계로 검토 화면을 열고 전체 요청에서 고르게 함 |
| 표가 없는 HTML 응답 (2판) | 기록·기본 검증만. 검토 화면에 "표가 없어 값을 꺼낼 수 없습니다" |
| 기록 크기 상한 초과 | 행동 묶음 300개에서 멈추고 알림. 스냅샷·표본은 잘라 저장 |

## 11. 배포 (2판)

- 리버스 프록시(nginx 등) 뒤에 둘 때 `/api/ieum/recorder/ws/` 경로에 WebSocket 업그레이드 헤더를 넘긴다.
- 서버 메모리에 맞춰 `IEUM_RECORDER_MAX_SESSIONS`를 정한다. 기록 세션 하나가 Chromium 하나를 띄운다.
- 서버가 있는 네트워크 위치에서 대상 시스템에 닿아야 한다(서버 브라우저가 접속한다).
- 클라우드 메타데이터 외에 막아야 할 관리 대역이 있으면 `IEUM_RECORDER_DENY`에 더한다.

## 12. 시험 계획

1. **공용 판정 함수 분리**: 크롤러 시험(527개)이 하나도 바뀌지 않고 통과해야 다음으로 넘어간다.
2. **단위 시험** (브라우저 없음)
   - HTML 변환: 열 이름·중복 이름·병합 칸·`_links`(`href`·`onclick`)·`fields`·`hidden`·화면 배치용 표 버리기·EUC-KR
   - 분석: 역할 판별, 값 연결(JSON·HTML 사본·`_links`), 입력값 출처 7단계, 숨은 토큰 → `browser`,
     같은 경로 다른 기능 나누기, 여러 출처 단계, 정책, 설명 초안, 날짜 모양 고정값 확신도
   - 검증 판정: JSON·HTML 구조 비교, 오류 응답, 실패 이유 코드, 원값 없는 입력(`needs_value`)
   - 가드: 운영 쓰기 붙잡기·승인·거절·시간 초과, 스테이징 통과, 로그인 판정(비밀번호 필드만, `csrfToken` 오인 없음),
     조회용 POST, 항상 차단 목록
   - 저장: 행동 묶음 덧붙이기, 재시작 시 중단 처리, 스크린샷 보관 규칙(확정 시 삭제, 7일)
   - 마스킹: ARIA 스냅샷이 마스킹되어 저장되고, 마스킹 뒤에도 핵심 판정이 된다
   - 상한: 서버 전체·사람당, 설정값 반영
   - 프레임: 느린 구독자에게 최신 프레임만 간다
3. **브라우저 e2e 시험** (`demo_legacy`, `IEUM_SKIP_BROWSER_TESTS=1`이면 건너뜀). 시험이 WebSocket으로 입력을 보낸다.
   - 읽기 업무(XHR): 조회 → 첫 행 상세 → 단계 2개, `poNo` 연결, 검증 두 번 통과
   - **읽기 업무(서버 렌더링, 2판)**: 시연 사이트에 폼 제출 → HTML 표 화면을 하나 더해, 조회 → 상세가
     `kind: "html"` 단계 2개와 표에서 꺼낸 값 연결로 정리되고 검증되는지
   - 쓰기 업무: 저장에서 멈춤 → 거절하면 발주가 생기지 않음 → 승인하면 생김 → Replay 직전 재승인
   - 한글: IME 조합으로 "한빛" 입력
   - 격리: 두 기록 세션의 쿠키와 기록이 섞이지 않음
   - 중단: 서버 재시작 흉내, Chromium 강제 종료 후 `interrupted`, 저장된 행동 묶음 유지
4. **콘솔 점검**: 전역 이름 충돌 확인, `confirm`·`alert` 미사용, 실제 화면으로 흐름 확인.

시연 사이트는 모듈 상태를 들고 있어 시험 사이에 `demo_legacy.reset()`이 필요하다(`ieum_state` 픽스처).

## 13. 구현 순서

1. 공용 판정 함수 분리 (기존 시험 그대로 통과)
2. 저장소 (기록 요약 스토어 + 행동 묶음 파일 + 보관 정리)
3. 쓰기 가드 (+ 항상 차단 목록)
4. 화면 중계 입력과 비동기 브라우저 실행 (+ 최신 프레임만)
5. HTML 변환
6. 행동 묶음 기록 (document 응답 포함, 모든 프레임 ARIA, 마스킹, 원값 메모리 보관)
7. 기록 세션과 관리자 (상한 둘, 브라우저 끊김, 세션 만료·업로드 안내)
8. API·WebSocket
9. 분석
10. Replay 검증
11. 종료 후 흐름, 확정(스크린샷 삭제), 단건 등록
12. 콘솔 화면
13. e2e 시험(시연 사이트 서버 렌더링 화면 포함)과 문서

## 다음 작업으로 넘기는 것

- **C안 — 여러 단계 도구**: 이 문서의 업무 기능 형식을 읽어 `engine`이 단계를 순서대로 실행하고, 도구 형식과
  MCP 배포 스냅샷이 단계를 담는다. 단계마다 출처·인코딩·실행 방식(`http`/`browser`)이 다를 수 있다.
- **AI 운전자**: 새 기록 화면에 "AI에게 맡기기(자연어 목표)"를 더한다. 실험에서 Stagehand 방식(`observe` 1회 +
  LLM 없는 `act` 재생)이 비용 대비 가장 나았다.
- **자동 탐색 묶음 추천**: 자동 탐색 결과를 공용 분석기에 넣어 "묶음 후보"를 보여주고 업무 기록 메뉴에서 확정한다.
- **분할 추천**: 기록 하나를 여러 업무로 나누자고 제안한다.
- **표가 아닌 HTML에서 값 꺼내기, 여러 페이지 목록 모으기.**
- **콘솔 사용자 로그인과 권한**: 이음 전체 작업. 생기면 사람당 상한과 기록 화면 접근을 계정 기준으로 바꾼다.
- **동시 기록 대기열.**
- **주소창**: 넣는다면 2절의 이동 범위 판단을 다시 한다.
