# 이음 웹 레코더 설계 (MVP)

작성일: 2026-10-10
대상 브랜치: `feature/ieum-web-recorder`

## 배경

사람이 레거시 웹 화면에서 업무 하나를 수행하면, 그 과정의 화면 조작과 네트워크 호출을 기록해
**다시 실행할 수 있는 업무 기능(Business Function)**으로 바꾸는 기능이다. 업무 기능은 나중에
MCP 도구 하나가 된다.

이전에는 같은 목적의 기능이 두 갈래로 있었다.

- 본체의 Chrome 확장 기록: 사용자의 평소 브라우저에서 트래픽을 관측한다. 쓰기 차단, 화면
  스냅샷, 원격 배포가 어렵다.
- 본체의 LLM 자동 탐색(aa82467): 이음 자동 탐색과 중복이라 `ce9274b`에서 지우고 이음으로 합쳤다.

이음 자동 탐색(`app/ieum/discovery`)은 메뉴를 전부 훑어 **낱개 API 목록**을 만든다. 어떤 API가
어떤 업무에서 어떤 순서로 쓰이는지는 모른다. 레코더는 그 빈자리, 즉 **API를 업무 단위로 묶는 일**을
맡는다.

### 실험으로 확인한 것 (2026-10-09, 버린 코드)

| 질문 | 결과 |
|---|---|
| 우리 가드(Playwright)가 브라우저를 쥐고, 다른 CDP 클라이언트가 조작해도 쓰기를 막을 수 있나 | 된다. Browser Use·Stagehand가 누른 저장 요청을 모두 가로챘다 |
| 쓰기를 가짜 `200 {}`으로 막으면 | 자율 에이전트가 생성 번호를 찾아 헤매 토큰이 4배(7.2만→29.9만)가 됐다. 가짜 응답은 쓰지 않는다 |
| 서버 브라우저 화면을 웹으로 중계하고 영상 위를 클릭하면 무엇을 눌렀는지 알 수 있나 | 12번 모두 정확, 전부 `isTrusted=true`. 좌표 환산(0.75배)도 맞았다 |
| 한글 입력 | IME 조합 후 `Input.insertText`로 "한빛"이 깨지지 않았다 |
| 승인 판단을 버튼 글자로 하면 | "승인대기" 행 클릭이 금지어 "승인"에 걸렸다. 판단은 **나가는 요청**으로 해야 한다 |
| 사용자 둘이 동시에 | 브라우저 세션별로 쿠키·기록이 섞이지 않았다 |
| 지연·프레임 | 같은 PC에서 입력→화면 반영 중앙값 20ms, 프레임 장당 약 39KB |

## 목표

1. 사용자가 이음 콘솔 안에서 서버 브라우저를 조작해 업무 하나를 기록한다(화면 중계).
2. 기록을 분석해 업무 기능 정의(단계, 단계 사이 값 연결, 입력값 출처, 정책)를 만든다.
3. 업무 기능을 실제로 다시 실행해 검증한다(Replay).
4. 사람이 검토 화면에서 고치고 확정한다. 단계가 하나인 업무는 이음 도구로 바로 등록한다.

## 비목표

- **여러 단계를 도구 하나로 실행** (실행 엔진·도구 형식·MCP 배포 스냅샷 확장). 다음 작업(C안)이다.
  다만 이번 업무 기능 형식은 C안이 그대로 읽을 수 있게 정한다.
- AI 에이전트가 운전자를 맡는 기록(자연어 목표). 다음 단계에서 새 기록 화면의 "운전자" 자리에 더한다.
- 자동 탐색 결과에서 묶음 후보 추천. 분석기만 공용으로 설계한다.
- 기록 하나를 여러 업무로 나누는 분할 추천. 근거 데이터(ActionSpan, 스냅샷)는 남긴다.
- 이음 콘솔 사용자 로그인과 권한(Keycloak 등). 이음 전체의 별도 작업이다.
- 파일 업로드, 드래그, 화면 상태까지 비교하는 검증.
- Git 소스 분석, MCP 빌더 연동(다른 담당).

## 확정한 결정

| 주제 | 결정 | 이유 |
|---|---|---|
| 화면 전달 | **처음부터 화면 중계** (CDP 화면 스트리밍 + 입력 역중계) | 실제 배포가 원격 웹서버·다중 사용자다. 로컬 창으로 먼저 만들면 두 번 만든다 |
| MVP 결과물 | **검증된 업무 기능 정의까지** (B안). 도구 등록은 단건만 | 우리 팀 경계가 "검증된 업무 기능"이다. 실행 엔진 확장은 정의가 확정된 뒤 그 모양에 맞춘다 |
| 로그인 | **자동 로그인, 안 되면 사람이 직접** | 서비스 계정이 있으면 언제든 재검증 가능. OTP·캡차·SSO·권한 부족이면 사람이 중계 화면에서 로그인 |
| 쓰기 | 운영은 **요청을 붙잡고 승인**, 스테이징은 통과. 가짜 응답 금지 | 실험 결과. 판단 기준은 버튼 글자가 아니라 나가는 요청 |
| 메뉴 | 새 메뉴 **"업무 기록"** | 업무 기능은 계속 쌓이고 다시 검증하는 자산이다. 운전자(사람/AI)와 무관하게 한 곳에 모인다 |
| 기록 중 화면 | 영상 왼쪽 크게 + 오른쪽 타임라인 | 업무를 하며 무엇이 잡히는지 바로 보인다 |

## 1. 전체 구조

```
[이음 콘솔 웹 화면]  업무 기록 메뉴
   │  REST: 기록 시작·종료·목록·검증·확정·등록
   │  WebSocket: 화면 영상 ↓ / 클릭·키 입력 ↑ / 승인 요청 ↕
   ▼
[이음 백엔드 (콘솔 프로세스)]
   ├─ recorder/session.py   기록 세션 = 사용자 한 명의 브라우저. 수명·상한·회수
   ├─ recorder/relay.py     CDP 화면 스트리밍, 입력 역중계, 좌표 환산, 한글
   ├─ recorder/guard.py     네트워크 기록 + 쓰기 붙잡기·승인 (공용 캡처 사용)
   ├─ recorder/trace.py     ActionSpan 기록 (행동 + 직전/직후 ARIA 스냅샷 + 네트워크)
   ├─ recorder/analyze.py   기록 → 업무 기능 (역할 판별, 값 연결, 입력값 출처, 정책)
   ├─ recorder/replay.py    Replay 검증
   └─ discovery/capture.py  crawler.py 에서 떼어 낸 공용 네트워크 캡처 (자동 탐색도 사용)
   ▼
[Chromium]  기록 세션마다 하나 (화면 없음)
```

### 브라우저 실행 위치

**콘솔 프로세스 안, 전용 스레드 하나의 Playwright 비동기 이벤트 루프**에서 모든 기록 세션을 돌린다.
기록 세션마다 Chromium을 따로 띄워 사용자 사이를 브라우저 프로세스 단위로 격리한다.

- 자동 탐색도 콘솔 프로세스의 스레드에서 Playwright를 돌린다. 같은 방식이다.
- 브라우저 작업은 대기가 대부분이라 GIL 문제가 없다. CLAUDE.md의 "정규식이 서버를 멈춘" 사례와 성격이 다르다.
- WebSocket이 콘솔에 바로 붙어 원격 배포 때 포트를 따로 열지 않는다.
- 사용자가 많아지면 세션별 프로세스로 옮길 수 있게 `session.py` 경계를 분명히 둔다.

브라우저는 기존 `discovery/browser.py` 순서(번들 Chromium → Chrome → Edge)로 찾는다.

### 운영 기본값 (설정으로 바꿀 수 있다)

| 항목 | 기본값 |
|---|---|
| 동시 기록 세션 | 4 (넘으면 대기) |
| 입력 없을 때 회수 | 10분 |
| 기록 최대 길이 | 30분 |
| 쓰기 승인 응답 대기 | 2분 (지나면 보내지 않음) |
| 서버 재시작 시 | 진행 중이던 기록은 `interrupted` |

### 격리의 범위

이음 콘솔에는 사용자 로그인이 없다(상단 사용자 이름은 `data/sources/workspace.json`의 고정값).
MVP의 격리는 **기록 세션 단위**다. 세션마다 브라우저가 따로이고, 세션 화면은 그 세션의 접속 토큰으로만
열린다. 기록자는 시작할 때 입력한 이름으로 남긴다.

## 2. 데이터 모델

세 층이다. 기록(Recording) → 행동 묶음(ActionSpan) → 업무 기능(BusinessFunction).

### 기록 (Recording)

```json
{
  "id": "rec_8f2a1c", "name": "9월 발주 상세 조회", "owner": "홍길동",
  "sourceBase": "http://10.20.4.30:8080/po", "env": "op",
  "login": { "mode": "auto", "recipe": { "loginRel": "/login.do", "actionRel": "/loginProc.do",
             "userField": "userId", "pwField": "userPw" } },
  "status": "recording",
  "startedAt": 1791600000, "endedAt": null,
  "spans": [],
  "approvals": [ { "spanSeq": 7, "req": "POST /poSave.do", "decision": "approve", "at": 1791600120 } ],
  "functionId": null
}
```

- `env`: `op`(운영) | `stg`(스테이징)
- `login.mode`: `auto`(서비스 계정, 비밀번호는 금고) | `manual`(사람이 직접, 비밀번호 저장 안 함)
- `recipe`는 필드 이름만 남긴다. 기존 `crawler._build_recipe`로 로그인 요청에서 뽑는다.
- `status`: `queued` → `recording` → `analyzing` → `verifying` → `review` → `confirmed`,
  또는 `failed` / `interrupted`

### 행동 묶음 (ActionSpan)

```json
{
  "seq": 5,
  "action": { "type": "click", "target": { "role": "button", "name": "조회", "id": "btnSearch", "frame": "main" },
              "value": null, "isTrusted": true, "t": 1791600050 },
  "pre":  { "url": "/poListView.do", "title": "발주 현황", "aria": "...", "shot": "rec_8f2a1c/5-pre.jpg" },
  "network": [
    { "method": "GET", "url": "/poList.do?fromDt=20260901&toDt=20260930", "status": 200,
      "req": "...", "res": "...", "rtype": "xhr", "held": false }
  ],
  "post": { "url": "/poListView.do", "aria": "...", "shot": "rec_8f2a1c/5-post.jpg" }
}
```

- `action.type`: `click` | `fill` | `select` | `submit` | `navigate` | `key`
- 행동이 끝나고 네트워크와 화면이 잠잠해지면 묶음을 닫는다. 그사이 나간 요청이 그 행동에 속한다.
- `network` 항목은 크롤러의 `Observed`와 같은 형식이다. 마스킹·파라미터 추론을 그대로 쓰고,
  크롤러 결과도 같은 분석기에 넣을 수 있다.
- 응답 원문은 저장하지 않는다. 마스킹한 표본만 남긴다(본체와 같은 원칙).
- 스크린샷은 파일로 두고 경로만 적는다.

### 업무 기능 (BusinessFunction)

```json
{
  "id": "bf_purchase_order_detail", "name": "발주 상세 조회", "desc": "기간 안의 발주를 조회하고 상세를 확인합니다",
  "source": { "base": "http://10.20.4.30:8080/po", "recordingId": "rec_8f2a1c", "made": "manual-record" },
  "inputs": [
    { "name": "fromDt", "type": "date", "source": "USER_INPUT", "ex": "20260901", "screenLabel": "발주일(시작)", "confidence": "high" },
    { "name": "toDt",   "type": "date", "source": "USER_INPUT", "ex": "20260930", "screenLabel": "발주일(끝)", "confidence": "high" }
  ],
  "steps": [
    { "id": "s1", "role": "core", "method": "GET", "path": "/poList.do",
      "params": [ { "a": "fromDt", "loc": "query", "from": "input.fromDt" },
                  { "a": "toDt",   "loc": "query", "from": "input.toDt" } ],
      "headers": { "X-Requested-With": "XMLHttpRequest" },
      "outputs": { "poNo": "$.resultList[0].PO_NO" } },
    { "id": "s2", "role": "core", "method": "GET", "path": "/poDetail.do",
      "params": [ { "a": "poNo", "loc": "query", "from": "s1.poNo" } ] }
  ],
  "references": [ { "method": "GET", "path": "/common/codeList.do", "role": "code" } ],
  "output": { "from": "s2", "fields": ["$.po.VEND_NM", "$.po.PO_AMT"] },
  "auth": { "mode": "session", "recipe": {} },
  "executionMode": "session",
  "policy": { "operation": "READ", "risk": "LOW", "approval": "NONE",
              "envPolicy": "op-auto", "sensitivity": null, "scope": null },
  "verification": { "status": "verified", "at": 1791600300,
                    "runs": [ { "kind": "same-values", "ok": true }, { "kind": "varied-values", "ok": true } ] },
  "evidence": { "s1": [5], "s2": [6] },
  "status": "confirmed"
}
```

설계 원칙:

1. **단계의 요청 형식은 지금 이음 도구의 파라미터 형식(`a`, `loc` 등, `gateway/spec.py`)을 따르고
   `from`(값의 출처)만 더한다.** C안의 실행 엔진은 단계마다 기존 `engine.build_request`를 부르고
   단계 사이에 값만 넘기면 된다.
2. **입력값 출처 6종**: `USER_INPUT`, `PREVIOUS_STEP_OUTPUT`, `SESSION_CONTEXT`, `SYSTEM_CONFIG`,
   `DERIVED`, `CONSTANT`. `from`은 `input.<이름>` | `<단계 id>.<출력 이름>` | `session.<키>` |
   `config.<키>` | `const:<값>` 중 하나다.
3. **정책 중 자동으로 채우는 것**: 작업 유형, 위험도, 승인 방식. 권한 범위와 민감도는 사람이 채운다.
4. **`evidence`**는 단계가 나온 ActionSpan 번호다. 검토 화면이 "왜 이 API인가"를 화면 캡처로 보여준다.
5. `executionMode`: `direct` | `session` | `browser`. Replay가 알아낸 값이다.

### 저장 위치

| 대상 | 위치 |
|---|---|
| 기록 | JSON 스토어 `recorder.recordings` |
| 업무 기능 | JSON 스토어 `recorder.functions` |
| 스크린샷 | `data/ieum/recorder/<기록 id>/` |
| 서비스 계정 비밀번호 | 금고 `rec:<기록 id>` (확정·등록 때 원본 시스템 키로 옮긴다) |

읽고-고쳐-쓰는 구간은 `with store.LOCK:`으로 감싼다(CLAUDE.md). 기록 하나의 크기에 상한을 두고
ARIA 스냅샷과 응답 표본을 자른다.

## 3. 분석 (기록 → 업무 기능)

규칙만으로 동작하고 LLM에 의존하지 않는다. LLM은 이름·설명을 다듬는 선택 기능이다.

1. **잡음 걸러내기**: 정적 파일, 범위 밖 도메인, 행동 없이 반복되는 요청(폴링), 로그인·로그아웃
   (로그인은 `auth`로 따로 둔다).
2. **역할 붙이기**

   | 역할 | 근거 |
   |---|---|
   | `core` | 행동 직후 나갔고, 응답 값이 직후 ARIA 스냅샷에 나타난다 |
   | `prereq` | 응답 값이 뒤 단계 요청에 쓰인다 |
   | `code` | 코드표 형태 응답 (`infer.detect_code_tables`) |
   | `page` | HTML 문서 요청 |
   | `noise` | 1단계에서 걸러진 것 |

3. **같은 API 묶기**: 값만 다른 경로는 `{id}`로 묶는다. 같은 API를 여러 번 불렀으면 단계 하나로 합친다.
4. **값 연결과 입력값 출처 분류** (공용 분석기의 핵심). 파라미터 값을 이 순서로 대조한다.

   | 순서 | 대조 대상 | 결과 |
   |---|---|---|
   | 1 | 사용자가 입력·선택한 값 (fill/select 행동, 입력란 값) | `USER_INPUT` + 화면 라벨 |
   | 2 | 앞 단계 응답 안의 값 | `PREVIOUS_STEP_OUTPUT` + JSONPath |
   | 3 | 로그인 정보·세션 응답·쿠키 | `SESSION_CONTEXT` |
   | 4 | 숨은 입력란, 여러 API 공통 값 | `SYSTEM_CONFIG` |
   | 5 | 날짜 계산처럼 보이는 값 | `DERIVED` (확신도 낮음, 확인 필요) |
   | 6 | 어디에도 안 맞고 늘 같은 값 | `CONSTANT` |

   같은 값이 여러 곳에 있으면 확신도를 낮게 매겨 검토 화면에서 묻는다. CSRF 토큰처럼 매번 바뀌는 값은
   `SESSION_CONTEXT`로 두고 "실행할 때 새로 받아야 함"으로 표시한다.
5. **단계 확정과 출력**: `core`와 `prereq`가 단계가 된다. `code`는 `references`에 두되, 그 응답이 입력으로
   쓰이면 단계로 올린다. 출력은 마지막 핵심 단계 응답 중 사용자가 마지막 화면에서 본 필드다.
6. **정책 추정**: 단계 중 가장 위험한 것을 업무 기능의 정책으로 쓴다.

   | 근거 | 작업 유형 | 위험도 | 승인 |
   |---|---|---|---|
   | 모두 GET, 승인 이력 없음 | READ | LOW | NONE |
   | 쓰기 + 저장·등록 | CREATE | MEDIUM | CONFIRM |
   | 쓰기 + 수정·변경 | UPDATE | MEDIUM | CONFIRM |
   | 쓰기 + 삭제 | DELETE | HIGH | HITL |
   | 쓰기 + 승인·결재·결제·이체 | APPROVE | CRITICAL | HITL |

재사용: `masking.Masker`, `infer.py`, `merge`의 경로 정규화.

## 4. Replay 검증

기록 종료 직후 자동으로 시작한다. 기록 브라우저는 검증이 끝날 때까지 닫지 않는다.

### 두 번 실행

1. **같은 값 재실행**: 기록 때 입력값 그대로 전 단계를 실행한다.
2. **다른 값 재실행**: `USER_INPUT`만 바꾼다. 값은 기록 안에서 고른다(목록 응답의 다른 번호, select의
   다른 옵션, 날짜 범위는 한 달 앞으로). 고를 값이 없으면 건너뛰고 "같은 값으로만 검증됨"으로 표시한다.

### 실행 방식 판별

1. **세션 HTTP**: 기록 세션 쿠키 + 보존 헤더(User-Agent, Referer, X-Requested-With)로 서버가 직접 호출한다.
   헤더는 WAF 때문에 필요하다(CLAUDE.md).
2. 실패하고 원인이 브라우저 의존(토큰·서명)으로 보이면 **브라우저 안 호출**: 기록 세션 페이지에서 `fetch()`.

성공한 방식을 `executionMode`로 남긴다. 인증 없이 되면 `direct`.

### 성공 판정

한 단계가 성공이려면 모두 만족해야 한다.

1. 2xx이고 로그인 화면으로 돌려보내지지 않았다(`session_auth.expired` 재사용).
2. 응답을 해석할 수 있고 기록 때와 구조(키 이름·타입)가 대부분 같다.
3. 오류 표시가 없다(`resultCode` 실패값, "권한이 없습니다" 같은 문구).
4. 다음 단계로 넘길 값을 실제로 꺼낼 수 있다.

### 실패 이유 코드

`auth_expired`, `waf_blocked`, `shape_mismatch`, `chain_broken`, `write_denied`, `browser_only`(실패 아님, 실행 방식 정보)

### 쓰기 단계

- 운영: 그 단계 직전에 다시 승인을 받는다. 거절하면 그 단계부터 실행하지 않고 `write_denied`.
- 스테이징: 승인 없이 실행한다.
- 쓰기 단계는 같은 값 재실행만 한다.

### 세션이 끊겼을 때

- `login.mode = auto`: 금고 계정으로 다시 로그인해 이어 간다(`session_auth`).
- `login.mode = manual`: 기록 세션이 살아 있는 동안만 검증한다. 끊기면 중계 화면을 열어 다시 로그인을 받는다.

### 안전장치

- 기록한 시스템 주소로만 보낸다.
- 운영 주소면 요청 간격 최소 0.6초(이음 탐색 정책과 같은 기준).
- 업무 기능 하나의 검증 횟수에 분당 상한.
- 응답은 마스킹한 뒤 저장한다. 모든 Replay 요청을 감사 이력에 남긴다.

재사용: `gateway/session_auth.py`, `gateway/engine.parse_body`, `discovery/verify.py`의 판정 규칙.

## 5. 쓰기 처리 (기록 중)

| 환경 | 쓰기 요청(POST·PUT·PATCH·DELETE)이 나갈 때 |
|---|---|
| 운영 | 가드가 요청을 붙잡고 콘솔에 승인 창을 띄운다. 승인하면 보내고, 거절하면 버린다. 가짜 응답은 쓰지 않는다 |
| 스테이징 | 그대로 보내고 기록에 쓰기라고 표시한다 |

- 판단 기준은 **나가는 요청**이다. 버튼 글자는 승인 창의 설명으로만 쓴다.
- 이름이 쓰기처럼 보이는 GET(`policy.risky_call`)도 운영에서는 같은 승인을 받는다.
- 승인 창이 떠 있는 동안 다른 입력을 막는다.
- 로그인 요청과 사용자가 지정한 조회용 POST(`readPost`)는 승인 없이 통과한다.
- 승인·거절 이력을 기록에 남긴다(감사, 정책 추정 근거).
- 자동 탐색의 쓰기 차단 규칙(가짜 응답으로 막기)은 바꾸지 않는다. 레코더만 다른 규칙을 쓴다.

## 6. 화면 (이음 콘솔 "업무 기록" 메뉴)

### 흐름

① 업무 기능 목록 → ② 새 기록 시작 → ③ 기록 중 → (자동 분석·검증) → ④ 검토·검증 → 확정 → ① 목록

- 목록 항목을 누르면 ④가 열린다. 기록 중인 항목은 ③으로 다시 들어간다.
- 원본 시스템 연결 마법사에는 "업무 기록으로 시작" 버튼만 두어 이 메뉴로 보낸다.

### ① 업무 기능 목록
업무 기능과 기록 중 항목. 상태(기록 중 / 검증됨 / 부분 검증 / 정책 미완 / 실패), 작업 유형, 단계 수.

### ② 새 기록 시작
업무 이름, 대상 시스템 주소, 환경(운영/스테이징), 로그인 페이지·아이디·비밀번호(선택), 기록하는 사람,
조회용 POST 경로(선택). 다음 단계에서 이 화면에 "운전자(사람/AI)" 선택을 더한다.

### ③ 기록 중
- 왼쪽에 서버 브라우저 영상(화면 폭에 맞춰 축소, 좌표 환산), 오른쪽에 타임라인 패널.
- 위 띠: 기록 시간, 업무 이름, **환경(운영은 붉게)**, 일시정지, 기록 종료, 열린 탭 목록.
- 타임라인: 행동 → 요청, 요청·쓰기·잡음 개수. 항목을 누르면 직전·직후 캡처와 요청 내용.
- 쓰기 승인 창: 영상 위에 뜨고 다른 입력을 막는다.
- 일시정지: 업무와 무관한 조작 동안 기록을 멈춘다(브라우저는 계속 쓸 수 있다).
- 대상 사이트의 `alert`·`confirm`은 콘솔에 같은 내용의 창으로 띄워 사용자가 답한다.

### ④ 검토·검증
- 왼쪽: 입력값 표(이름, 화면 라벨, 출처, 기록 값, ⚠ 확인 필요), 단계 흐름 카드(값 연결과 근거 캡처),
  단계에 넣지 않은 요청(역할별, 단계로 올리기).
- 오른쪽: 검증 결과(두 번 실행, 실행 방식, 실패 이유), 정책(자동 추정 + 사람 입력 ⚠), 이음 도구 등록.
- 2단계 이상이면 "도구 하나로는 다음 작업에서 지원"으로 안내하고, 단계를 낱개 도구로 등록하는 버튼만 둔다.
- ⚠ 칸이 비어 있어도 확정할 수 있다. 목록에 "정책 미완"으로 표시한다.

### 콘솔 구현 규칙

- 메뉴 추가: `state.js`의 `VIEWS`, `js/menu/recorder.js`, `index.html`, `main.js`의 `VFN`.
- classic script라 전역 이름이 충돌하면 파일이 통째로 실행되지 않는다. 새 전역 이름은 먼저 grep한다.
- `window.confirm`·`alert`·`prompt`를 쓰지 않는다. 승인 창은 화면 안 창이다.
- 콘솔에 처음으로 WebSocket이 들어온다. 접속 토큰은 세션 시작 응답으로 받는다.

## 7. 오류 처리

원칙: **기록은 잃지 않는다**(행동 묶음을 닫을 때마다 저장). **애매하면 안전한 쪽**(마스킹 실패 시 원문 저장 안 함,
승인 응답 없으면 보내지 않음).

| 상황 | 처리 |
|---|---|
| 브라우저를 띄우지 못함 | 기존 탐색 순서를 따르고, 모두 실패하면 설치 안내 |
| 동시 기록 상한 초과 | 시작하지 않고 대기. 자리가 나면 알림 |
| 사용자가 탭을 닫음·네트워크 끊김 | 세션 유지(10분). 다시 열면 영상과 기록이 이어진다 |
| 10분 동안 입력 없음 | 브라우저 회수, 기록은 `interrupted`. 저장된 행동 묶음으로 분석 가능 |
| 서버 재시작 | 진행 중이던 기록은 `interrupted` |
| 자동 로그인 실패 | 중계 화면을 사용자에게 넘겨 직접 로그인 |
| 기록 중 세션 끊김 | 타임라인에 "세션 만료" 표시, 다시 로그인 요청. 기록은 이어진다 |
| 쓰기 승인 응답 없음(2분) | 보내지 않음으로 처리하고 알림 |
| 대상 사이트 `alert`·`confirm` | 콘솔 창으로 사용자에게 묻고 답을 전달(자동 탐색처럼 항상 취소하지 않음) |
| 새 창·팝업 | 탭 목록에 추가하고 영상을 새 탭으로 전환. 기록은 모든 탭에서 계속 |
| 파일 다운로드 | "파일 응답"으로 기록, 파일은 저장하지 않음 |
| 파일 업로드 | MVP 미지원. 안내 문구 |
| 핵심 요청을 못 찾음 | 빈 단계로 검토 화면을 열고 전체 요청에서 고르게 함 |
| 기록 크기 상한 초과 | 스냅샷·표본을 자르고 "일부 생략됨" 표시 |

## 8. 시험 계획

1. **공용 캡처 분리**: `crawler.py`의 네트워크 구역(`_route`/`_route_inner`, `_on_response`/`_flush`,
   `_keep_headers`, `_room`, `_record_event`, `_count`/`_settle`)을 `discovery/capture.py`로 옮긴다.
   **기존 시험(527개)이 하나도 바뀌지 않고 통과**해야 다음으로 넘어간다.
2. **단위 시험** (브라우저 없음, 미리 만든 기록 JSON 사용)
   - 분석: 역할 판별, 값 연결, 입력값 출처 6종, 경로 묶기, 정책 추정
   - 검증 판정: 구조 비교, 오류 응답 감지, 실패 이유 코드
   - 가드: 운영 쓰기 붙잡기·승인·거절·시간 초과, 스테이징 통과, 로그인·조회용 POST 통과, 위험 이름 GET
3. **브라우저 e2e 시험** (`demo_legacy` 대상, `IEUM_SKIP_BROWSER_TESTS=1`이면 건너뜀). 시험이 WebSocket으로
   클릭과 입력을 보낸다.
   - 읽기 업무: 로그인 → 발주 현황 조회 → 첫 행 상세 → 종료 → 단계 2개, `poNo` 연결, 검증 두 번 통과
   - 쓰기 업무: 발주 등록 → 저장에서 멈춤 → 거절하면 발주가 생기지 않음 → 승인하면 생김 → Replay 직전 재승인
   - 한글: IME 조합으로 "한빛" 입력
   - 격리: 두 기록 세션의 쿠키와 기록이 섞이지 않음
   - 중단: 서버 재시작 흉내 후 `interrupted`, 저장된 행동 묶음 유지
4. **콘솔 점검**: 전역 이름 충돌 확인, `confirm`·`alert` 미사용.

시연 사이트는 모듈 상태를 들고 있어 시험 사이에 `demo_legacy.reset()`이 필요하다(`ieum_state` 픽스처).
