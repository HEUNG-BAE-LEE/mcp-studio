# 관리자 화면 재구성 설계

작성일: 2026-07-26
대상 브랜치: `docs/target-site-scenarios`

## 배경

`~/Downloads/mcp-flow-studio-source`는 **동작하지 않는 UI 목업**이다. `app/page.tsx`
316줄이 전부고 데이터는 전부 하드코딩이며, DB 스키마는 비어 있고 백엔드도 캡처
기능도 없다. Next.js + Cloudflare D1 스택이라 우리(Vite + React + FastAPI)와도
맞지 않는다.

값어치는 **그림**에 있다. 목업이 그리는 5단계가 우리가 실제로 만든 파이프라인과
거의 1:1로 대응한다.

| 목업 (그림) | 우리 (실제 동작) |
|---|---|
| URL 등록 | 확장 기록 시작 |
| 액션 기록 | 클릭 + fetch/XHR 후킹 |
| API 분석 · 신뢰도 96% | 점수화 ★9 + 추천 사유 |
| MCP 생성 · 도구 정의 + JSON | ActionEdit + tool 변환 |
| 테스트 | LLM 콘솔 |

목업은 "민감정보 보호 적용"이라는 문구만 띄우지만, 우리는 URL 쿼리·요청 본문·응답
샘플 세 곳에서 실제로 마스킹한다. **저쪽은 흉내를 내고 우리는 실제로 한다.**

동시에 이 작업은 현재 관리자 화면의 실제 약점을 메운다 — 목록 화면이 하나도 없어
세션 번호를 URL에 직접 쳐야 한다.

## 목표

1. 목업의 디자인 언어와 레이아웃 골격을 우리 관리자 화면에 이식한다.
2. 없던 목록 화면과 내비게이션을 만들어 URL을 직접 치지 않아도 되게 한다.
3. 화면에 뜨는 모든 숫자와 문구는 실제 데이터로 뒷받침한다.

## 비목표

- Next.js / Cloudflare / Drizzle / Tailwind 도입
- 목업의 하드코딩 데이터와 서사(Playwright 레코더, 네트워크 프록시) 이식
- 사용량 집계, 산출물(HAR·OpenAPI), 회귀 테스트 — 기능이 없으므로 화면도 만들지 않는다
- 반응형·모바일 대응 (데모는 데스크톱 촬영)

## 1. 가져오는 것

`app/globals.css`의 CSS 변수 7개와 클래스 94개를 `apps/admin/src/styles/app.css`
한 파일로 이식한다. 첫 줄의 `@import "tailwindcss"`는 제거한다 — 목업은 유틸리티
클래스를 쓰지 않고 94개 클래스를 전부 손으로 썼으므로, 이 import는 장식이며
의존성만 늘린다.

### 폰트

목업은 `Inter, Pretendard, "Noto Sans KR"`를 부르지만 셋 다 저장소에 없어 macOS에서
시스템 폴백으로 떨어진다. 웹폰트 파일을 추가하는 대신 macOS 한글 스택을 앞에 둔다:

```css
font-family: -apple-system, "Apple SD Gothic Neo", Pretendard, "Noto Sans KR",
             system-ui, sans-serif;
```

파일 추가 없이 촬영 화면에서 한글이 또렷하다.

### 셸 컴포넌트 (신설 4개)

- `Sidebar` — 내비게이션 4항목
- `Topbar` — 브레드크럼
- `Stepper` — 세션 컨텍스트 안에서만 표시
- `Toast` — 조작 성공 알림, 2.2초 후 자동 소멸

## 2. 화면과 라우트

| 라우트 | 화면 | 상태 |
|---|---|---|
| `/` | 프로젝트 목록 | 신설 |
| `/projects/:id` | 세션 목록 + 액션 목록 | 신설 |
| `/sessions/:id` | 후보 분석 | 기존 재스타일 |
| `/actions/:id` | 액션 편집 | 기존 + 단건 로드 |
| `/projects/:id/console` | 테스트 콘솔 | 기존 재스타일 + 경로 이동 |

사이드바는 순수 내비게이션이고, 스테퍼는 세션 컨텍스트 안의 진행 표시다. 목업은
둘을 사이드바 하나로 합쳤는데, 세션이 여러 개 쌓이면 "현재 단계"가 무엇을 가리키는지
모호해지므로 분리한다.

### 액션 생성 경로

`/actions/new?requestId=N`은 액션을 만든 뒤 곧바로 `/actions/:id`로 이동시킨다.
생성은 한 번, 이후는 조회다. 이월해둔 "페이지를 열 때마다 Action 행이 생긴다"는
문제가 이 구조에서 자연히 사라진다.

### 콘솔 경로 이동

`/console` → `/projects/:id/console`. 직전 작업에서 넣은 프로젝트 드롭다운은
경로 파라미터로 대체되므로 제거한다.

### 스테퍼의 1~2단계

5단계 중 ①기록 시작과 ②클릭 기록은 **확장 프로그램에서** 일어나며 관리자 화면이
아니다. 세션이 존재한다는 것 자체가 두 단계를 거쳤다는 뜻이므로, 스테퍼는 1~2를
항상 완료로 표시하고 3~5 중 현재 라우트에 해당하는 단계를 현재로 표시한다.

## 3. 백엔드 추가

```
GET    /api/recording-sessions/{id}
       → {id, projectId, projectName, startedAt, endedAt, status}
GET    /api/projects/{id}/recording-sessions
       → [{id, startedAt, endedAt, status, requestCount, topScore}]
GET    /api/actions/{id}
       → {id, projectId, name, toolName, description, actionSpec, status}
DELETE /api/recording-sessions/{id}
DELETE /api/actions/{id}
```

`GET /api/recording-sessions/{id}`가 필요한 이유는 브레드크럼이다. `/sessions/:id`가
쓰는 기존 `candidates` 엔드포인트는 요청 목록만 돌려주고 프로젝트 id도 이름도 없어
"Projects / 국토교통부 실거래가 / 세션 #3"을 그릴 수 없다. 이미 리뷰를 통과한
`candidates`의 응답 형태를 바꾸는 대신 단건 조회를 새로 추가한다.

`requestCount`는 그 세션의 `NetworkRequest` 개수이고, `topScore`는 그중 최고 점수다.
아직 채점 전이거나 요청이 없으면 `topScore`는 `null`이다 — 0으로 내리면 "점수 0점"과
구분되지 않는다.

세션 삭제는 자식 행(`InteractionEvent`, `NetworkRequest`)을 함께 지운다. SQLite에
ON DELETE CASCADE를 걸지 않았으므로 라우터에서 명시적으로 지운다. `Action`은
네트워크 요청을 참조하지 않고 `action_spec`에 값을 복사해 두므로, 세션을 지워도
액션은 그대로 동작한다 — 액션까지 함께 지우지 않는다.

액션 상태 전환은 기존 `PUT /api/actions/{id}`를 그대로 쓴다 — 이미 `VALID_STATUS`
검증과 한국어 422를 갖추고 있다.

## 4. 화면에 뜨는 값의 출처

| 화면 요소 | 실제 출처 |
|---|---|
| 후보 점수 ★9 | `NetworkRequest.score` |
| 추천 사유 | `scoring.py`가 만든 사유 문자열 |
| 보안 · 마스킹 8 rules | `masking.py`의 `SENSITIVE_KEYS` 상수를 렌더 |
| 실행 결과 200 · 126ms · 11건 | `execute_action` 반환값 |
| 프로젝트 · 세션 목록 | 실제 테이블 |
| 액션 상태 DRAFT/ACTIVE | `Action.status` |

점수는 목업처럼 백분율로 바꾸지 않고 `★9` + 사유 문자열을 그대로 쓴다. 이미
카메라 앞에서 검증된 표기이고, 백분율로 환산하면 근거 없는 정밀도를 만든다.

## 5. 빈 화면 상태

촬영 절차가 `rm -f dev.db`로 시작하므로 **카메라가 처음 보는 화면은 세션 0개,
액션 0개다.** 목업은 데이터가 항상 있다고 가정해 빈 상태 디자인이 없다. 세 곳에
문구를 둔다.

| 위치 | 문구 |
|---|---|
| 프로젝트 목록 비었을 때 | 아직 프로젝트가 없습니다. 확장 프로그램에서 이름을 입력하고 기록을 시작하면 여기에 나타납니다. |
| 세션 목록 비었을 때 | 기록된 세션이 없습니다. 확장 프로그램에서 기록을 시작해 보세요. |
| 액션 목록 비었을 때 | 만들어진 액션이 없습니다. 세션에서 API 후보를 골라 액션을 만들 수 있습니다. |

세션 상세의 "이 세션에는 클릭과 연결된 요청이 없습니다"는 이미 있으므로 유지한다.

## 6. 확장 프로그램

**전송 후 관리자로 넘어갈 길이 없다.** 사이드 패널 코드 어디에도 관리자 주소가
없어, 지금은 기록을 마친 뒤 세션 번호를 사람이 알아내 URL을 쳐야 한다. 영상에서도
장면 4→5 전환이 여기서 끊긴다.

전송이 성공하면 사이드 패널에 세션 번호와 **"관리자에서 열기"** 버튼을 띄우고,
`http://localhost:5173/sessions/{id}`를 새 탭으로 연다. 주소는 `background.ts`의
`API_BASE`와 같은 방식으로 상수에 두고 데모 전용임을 주석에 남긴다.

사이드 패널에도 같은 색·폰트를 적용한다. 배경 상태 기계(`chrome.storage.session`,
`enqueue`, `byteSize`)는 건드리지 않는다.

## 7. 조작 기능

- **삭제** — 세션·액션 목록에서 지운다. `window.confirm`은 쓰지 않는다. 브라우저
  모달은 자동화를 막고 촬영 화면에서도 튄다. 대신 인라인으로 "정말 지울까요?
  [지우기] [취소]"를 같은 행에 펼친다.
- **액션 상태 전환** — 목록에서 DRAFT ↔ ACTIVE를 바꾼다. 콘솔은 ACTIVE만 노출하므로
  왜 콘솔에 안 뜨는지를 화면에서 바로 알 수 있다.
- **토스트** — 저장·활성화·삭제 성공 시 표시.

## 9. 선행 확인

직전에 들어간 **프로젝트 이름 자유 입력**(commit `d2598a3`)을 아직 브라우저에서
확인하지 않았다. 그 위에 화면을 새로 얹기 전에 확장 → 백엔드 → 관리자 경로가
실제로 도는지 먼저 눈으로 본다. 이것이 첫 작업이다.

## 10. 테스트

- 백엔드 신규 엔드포인트 5개는 단위 테스트를 쓴다. 삭제는 자식 행이 함께 지워지는지,
  없는 id는 한국어 404인지 확인한다.
- 화면은 브라우저 수동 검증으로 본다. 특히 빈 상태 세 곳은 데이터를 지운 상태에서
  직접 눈으로 확인한다 — 촬영 첫 장면이기 때문이다.
- 기존 70개 백엔드 테스트와 13개 확장 테스트는 계속 통과해야 한다.

## 11. 규모

백엔드 5개 엔드포인트, 신규 화면 2개, 재스타일 3개, 셸 4개, 확장 1곳, 문서 3건.
태스크 7~8개로 본다.
