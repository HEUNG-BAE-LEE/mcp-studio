# 이음 업무 도구 설계 — 기록한 업무 하나를 도구 하나로

- 작성일: 2026-10-12
- 상태: 1판 (사용자 검토 대기)
- 앞선 설계: `2026-10-10-ieum-web-recorder-design.md` (업무 기록 4판)

## 배경

업무 기록은 사람이 한 업무(예: 네이버 경제 목록 → 두 번째 기사)를 단계로 나누고 단계 사이 값을 이어 검증까지 한다.
그런데 등록하면 **단계마다 도구 하나**가 된다. 네이버 기록이라면 "섹션 목록" 도구와 "기사" 도구가 따로 생기고,
기사 도구는 언론사·기사 번호(`id`·`id2`)를 필수로 받는다. 그 값은 목록 화면의 링크 안에만 있고 목록 도구의 응답 매핑에는
링크가 없어서, AI 는 "경제 두 번째 기사"를 실행할 방법이 없다. 기록·검증에서 이어 둔 연결(`s1.links[…][1.0/1]`)이 등록에서 끊긴다.

또 확정과 등록이 따로 놀아서 확정해도 변환 스튜디오에 아무것도 생기지 않고, 등록한 도구에는 엉뚱한 안내 문구
("명세를 읽어 자동으로 만든 도구 후보")가 뜬다. 자동 탐색은 "도구 후보 N개 등록 → [변환 스튜디오 열기] → 근거 보기 → 검토 완료"
흐름이 갖춰져 있다.

## 목표

1. 검증을 통과한 **조회 업무**를 확정하면 **업무 도구 하나**가 변환 스튜디오에 원본 시스템 도구처럼 올라간다.
2. 업무 도구 하나를 부르면 기록한 단계를 차례로 실행하고 단계 사이 값을 잇는다(검증 엔진과 같은 규칙).
3. 목록에서 고르는 업무는 세 방식으로 부를 수 있다: 아무것도 안 주면 목록, `index`(몇 번째) 또는 `match`(찾을 글자)를 주면 그 항목의 상세.
4. 테스트 실행·배포한 MCP 서버·호출 로그·호출 한도는 지금 도구와 같은 경로를 탄다.
5. 검증 엔진과 실행 엔진은 같은 코드다(검증은 됐는데 실행은 다르게 되는 일을 막는다).

## 비목표 (이번 판)

- **쓰기가 섞인 업무 도구.** 배포한 MCP 서버에 호출별 승인 절차가 없다. 쓰기 단계가 하나라도 남은 업무는 업무 도구로 만들지 않고
  지금처럼 단계별(확인 필요) 도구로만 등록한다. 쓰기 업무 도구는 배포 서버의 HITL 승인을 만든 뒤 따로 설계한다.
- **브라우저에서만 돌아가는 단계**(`exec: "browser"`, 화면마다 새로 읽는 숨은 토큰). 실행기에는 브라우저가 없다. 그런 업무는 단계별 도구만 제안한다.
- **고르는 지점이 둘 이상인 업무**(목록 → 상세 → 하위 목록 → 상세). 이번에는 첫 고르는 지점 하나만 `index`/`match` 로 열고, 그 뒤 연결은 기록 때 순번을 쓴다.
- 스튜디오에서 단계를 고치는 것. 단계는 업무 기록에서 고치고 다시 등록한다.

## 확정한 결정

| 결정 | 이유 |
|---|---|
| 업무 도구는 스튜디오 도구 저장소의 새 종류 `kind: "flow"` | 원본 시스템별 목록·공개·배포·로그를 그대로 쓴다 |
| 등록하는 순간 단계 사본을 도구 안에 얼린다 | 배포와 같은 스냅샷 원칙. 기록을 고쳐도 다시 등록하기 전에는 도구가 그대로다 |
| 실행 엔진을 `app/ieum/flow/` 로 옮겨 레코더 검증과 게이트웨이가 함께 쓴다 | 엔진이 둘이면 판정이 어긋난다 |
| 아무 인자 없이 부르면 목록, `index`·`match` 면 상세 (사용자 결정: "셋 다") | AI 가 먼저 목록을 보고 고를 수도, 바로 고를 수도 있다 |
| 조회 업무만 | 배포 서버에 승인 절차가 없다 |
| 확정과 등록을 한 버튼으로 | "확정하면 스튜디오에 보인다"는 기대와 자동 탐색 흐름에 맞춘다 |

## 1. 구조

```
업무 기록 검토 화면 ──[확정하고 도구로 등록]──▶ recorder/service.register_flow
                                                   │  단계 사본·입력·고르는 지점·응답 매핑을 얼린다
                                                   ▼
                                   스튜디오 도구 저장소 (kind: "flow")
                                                   │
         테스트 실행(/playground) · 배포 MCP 서버(runtime) ─▶ gateway/runner.run_tool ─▶ engine.invoke
                                                                                   │ kind == "flow"
                                                                                   ▼
                                                                         flow.runner.invoke
                                                                                   ▲
                                         recorder/replay.run_once (검증) ──────────┘ 같은 단계 실행 코드
```

### 실행 엔진 옮기기 (`app/ieum/flow/`)

레코더 `replay.py` 에서 **기록 세션(Playwright)에 묶이지 않은 부분**을 옮긴다.

| 옮기는 것 | 지금 위치 |
|---|---|
| 값 채우기(`input.`, `const:`, `config.`, `session.`, `<단계>.<출력>`) | `replay._value` |
| 앞 응답에서 값 꺼내기(`links[틀@묶음][k.j/n]` 포함) | `analyze.get_path` 와 링크 틀 함수들 |
| HTTP 전송(쿠키 도메인 맞추기, 기록한 문자 집합) | `replay.HttpTransport` |
| 성공 판정(세션 만료·HTTP 상태·오류 화면·응답 모양) | `replay.judge` |
| 경로 자리 검사·차단 주소 재확인·가린 값 전송 금지 | `replay.run_once` 안 |

레코더 쪽에 남는 것은 `BrowserTransport`, 기록 세션의 원값 지도(`trace.raw`), 기록 화면 승인 창(`guard.ask`)이다.
`replay.run_once` 는 옮긴 단계 실행기를 불러 쓰고, 지금 시험(`test_ieum_recorder_replay.py` 등)이 그대로 통과해야 한다.
배포한 MCP 서버 프로세스가 이 모듈을 불러오므로 Playwright·레코더 세션을 import 하지 않는다.

## 2. 업무 도구 데이터

스튜디오 도구 저장소(`repositories/studio.py`)의 한 항목:

```json
{
  "id": "naver_econ_article", "kind": "flow", "title": "네이버 뉴스 경제 기사 읽기", "desc": "…",
  "status": "review", "mode": "read", "exec": "auto",
  "params": [
    {"o": "id", "a": "id", "at": "string", "loc": "input", "rule": "keep", "req": true, "ex": "101", "d": "섹션 번호"},
    {"o": "index", "a": "index", "at": "integer", "loc": "pick", "rule": "keep", "req": false, "d": "목록에서 몇 번째 항목(1부터)"},
    {"o": "match", "a": "match", "at": "string", "loc": "pick", "rule": "keep", "req": false, "d": "목록 행 글자에 이 말이 든 첫 항목"}
  ],
  "flow": {
    "version": 1,
    "steps": [ {"id": "s1", "base": "https://news.naver.com", "method": "GET", "path": "/section/{id}", "params": [...],
                "headers": {}, "outputs": {...}, "kind": "html", "charset": null,
                "recordedShape": [...], "recordedErrSeen": [...]}, {"id": "s2", ...} ],
    "pick": {"list": "s1", "step": "s2", "tpl": "/mnews/article/{id}/{id2}", "group": "ul.sa_list>li.sa_item._SECTION_HEADLINE"},
    "verifiedAt": 1791721591.0
  },
  "res": [ … 마지막 단계 응답 매핑 … ],
  "rec": {"function": "bf_…", "recording": "rec_…"}
}
```

- `params` 는 지금 도구와 같은 모양이라 MCP 입력 스키마(`engine.visible_params`)·스튜디오 입력 표가 그대로 읽는다.
  `loc: "input"` 은 업무 입력, `loc: "pick"` 은 고르기 인자다. 이름이 업무 입력과 겹치면 `index_`·`match_` 로 피한다.
- 단계 사본(`flow.steps`)에는 응답 원문(`recordedRes`)을 넣지 않는다. 판정에 쓰는 **응답 모양**(`htmltable.shape`·JSON 키 경로 집합)과
  기록 때 본 오류 문구(`errSeen`)만 넣는다. 가린 값은 `_scrub` 로 지금처럼 비운다.
- 배포 스냅샷(`runtime/manifest.py`)은 `disc`·`calls` 만 빼므로 `flow` 는 그대로 얼어 들어간다.
- 스튜디오 저장(`save_tool`)은 받은 필드를 덮어쓰므로, 화면은 `flow` 를 보내지 않고 서버는 `flow` 를 받으면 무시한다
  (단계는 업무 기록에서만 바뀐다).

## 3. 실행 (`flow.runner.invoke(source, tool, args, ctx)`)

`engine.invoke` 가 `tool.get("kind") == "flow"` 이면 넘긴다. 돌려주는 값은 지금과 같은 `(result, trace)` 다.

1. **입력 확인.** 필수 업무 입력이 없으면 오류. `index` 는 1 이상 정수, `index` 와 `match` 를 함께 주면 `index` 를 쓴다.
2. **고르는 지점 앞까지 실행.** 단계를 차례로 보낸다. 인증은 단계 주소(`base`)에 맞는 원본 시스템의 금고 값으로 붙인다
   (지금 `auth_headers`·`session_auth`). 한 호출 안의 쿠키는 단계 사이에 이어진다.
3. **고르기.**
   - 인자가 없으면 목록 단계 응답의 그 묶음 행들을 돌려주고 끝낸다:
     `{"items": [{"index": 1, "text": "행 글자(120자, 가림)"}, …최대 20개], "total": 행 수, "hint": "index 나 match 로 다시 부르면 상세를 가져옵니다."}`
   - `index` 면 그 행, `match` 면 행 글자(공백 정리·대소문자 무시)에 그 말이 든 첫 행. 없으면 오류 `no_match`(목록을 함께 실어 준다), 범위를 넘으면 `index_out_of_range`.
   - 고른 행의 순번으로 고르는 단계의 출처 `links[틀@묶음][k.j/n]` 의 `k` 만 바꿔 값을 꺼낸다. `j`·`n` 은 기록 그대로라
     행 모양이 다르면 지금처럼 `chain_broken` 이다.
4. **나머지 단계 실행.** 그 뒤 연결은 기록 때 순번을 쓴다.
5. **결과.** 마지막 단계 응답을 `convert_response(tool, data)` 로 바꾼다. HTML 이면 사본(표·이름값, 링크 후보는 뺀다)이 대상이다.
   고른 항목을 `"picked": {"index": 2, "text": "…"}` 로 함께 싣는다.

### 지키는 규칙 (지금 재실행 엔진과 같다)

- 가린 값은 경로·헤더·쿼리·폼·JSON 본문 어디로도 보내지 않는다(`masked_value` 오류).
- 경로 자리 값이 `.`·`..` 이거나 `/`·`\` 를 품으면 보내지 않는다. 정규화한 최종 주소로 차단 목록(`scope.blocked`)을 다시 본다.
- 운영 주소로 가는 단계 사이 간격 0.6초. 한 호출 전체 시간 상한 60초, 단계 수 상한 10.
- HTML 응답은 사본을 만들 때만 1MB(`htmltable.MAX_SCAN`)까지 읽는다.
- 세션 인증 원본에서 로그인 화면으로 튕기면 `session_auth` 로 한 번 다시 로그인해 그 호출을 처음부터 다시 실행한다(조회뿐이라 안전하다).

### 오류 이유 코드

`missing_input`, `no_match`, `index_out_of_range`, `chain_broken`, `masked_value`, `blocked`, `auth_expired`, `http_error`,
`waf_blocked`, `error_response`, `shape_mismatch`, `timeout`. 단계 id 와 함께 `ToolError` 로 돌려준다. 문구는 한국어다.

### 실행 기록 (trace)

지금 키(`args`, `aiResult`, `convertMs`, `sourceMs`)에 `steps: [{id, originRequest, originResponse(8000자), sourceMs, ok, reason}]` 를 더한다.
`originRequest`·`originResponse` 는 마지막 단계 것을 그대로 두어 지금 화면이 깨지지 않게 한다. 쿠키·인증 헤더는 지금처럼 가린다(`_redact`).

## 4. 등록 (`recorder/service.register_flow`)

조건(하나라도 어기면 400 과 이유):
- 검증 결과 `verified` 또는 같은 값 실행 성공(`partial` 도 같은 값이 성공이면 허용).
- 남은 단계가 모두 조회: GET/HEAD 이거나, 사람이 "조회로 확정"한 POST(`writeWhy == "사람이 지정"` 이고 `write == false`).
- `exec: "browser"` 단계가 없다.
- 단계 1~10개.

만드는 것:
- 고르는 지점: 출처가 `links[틀@묶음][…]` 꼴인 첫 단계. 없으면 고르기 인자 없는 업무 도구(단계만 이어 실행).
- 업무 입력: 업무 기능의 사용자 입력(`input.*`) 중 남은 단계가 쓰는 것. 가린 기록 값은 예시를 비운다(지금 `_tool_from_step` 규칙).
- 응답 매핑: 마지막 단계의 `infer.build_res`(지금과 같다).
- 원본 시스템: 기록을 시작한 주소의 `proto: "disc"` 원본(지금 `_register` 와 같은 규칙). 다른 주소 단계의 원본도 지금처럼 만든다(인증을 찾기 위해).
- 다시 등록하면 같은 업무 기능(`rec.function`)의 업무 도구를 제자리에서 바꾼다(이름·id·호출 수 유지).

확정과 묶기: `POST /recorder/functions/{id}/confirm/` 에 `{"register": "flow"}` 를 실으면 확정 뒤 곧바로 등록하고 등록 결과를 함께 돌려준다.
등록 조건을 못 채우면 확정도 하지 않는다(화면이 이유를 보여 준다). 단계별 등록(`register_steps`)은 그대로 둔다.

## 5. 화면

### 업무 기록 검토 화면 (`recorder.js`)

- 마지막 카드 "이음 도구로 등록":
  - 주 버튼 **[확정하고 도구로 등록]** — 조건을 못 채우면 막고 이유를 버튼 아래에 적는다(예: "쓰기 단계 s4 가 남아 있습니다. 건너뛰거나 단계별로 등록하세요").
  - 보조 버튼 [단계별로도 등록] — 지금 동작.
- 등록이 끝나면 자동 탐색과 같은 안내: "업무 도구 1개를 등록했습니다. 변환 스튜디오에서 설명을 검토한 뒤 공개하세요. [변환 스튜디오 열기]".

### 변환 스튜디오 (`studio.js`)

- 원본 작업 칸: 업무 도구면 단계 흐름을 그린다 — `s1 GET /section/{id}` → `목록에서 고름(index·match)` → `s2 GET /mnews/article/{id}/{id2}`.
  지금 `opLabel`·미리보기 원본 요청은 `kind == "flow"` 이면 이 흐름 표시로 바꾼다.
- 안내 띠(검토 대기): "업무 기록으로 만든 도구입니다 · 검증됨(2026-10-11) · 단계 2개 · [기록 보기] · [검토 완료]".
  업무 기록이 아닌 단계별 도구(`rec` 만 있고 `kind` 없음)도 "업무 기록의 한 단계로 만든 도구입니다. 앞 단계 값이 필요한 입력: id, id2" 띠를 단다.
  지금 뜨는 "명세를 읽어 자동으로 만든 도구 후보" 문구는 이 두 경우에 뜨지 않게 한다.
- 고칠 수 있는 것: 이름·설명·입력 설명·응답 매핑. 단계는 읽기 전용이고 "단계는 업무 기록에서 고친 뒤 다시 등록합니다"라고 적는다.

### 테스트 실행 (`playground.js`, `convert.js`)

실행 기록에 단계별 요청·응답을 차례로 그린다(`trace.steps`). 없으면 지금처럼 하나만 그린다.

### 배포

바꾸지 않는다. 업무 도구도 `status == "done"` 이어야 배포에 들어간다.

## 6. 시험

- `flow` 모듈 단위: 값 채우기, `links[…][k.j/n]` 의 k 바꾸기, 행 모양이 다르면 `chain_broken`, 가린 값 금지, 경로 자리 검사, 차단 주소.
- 실행(로컬 HTTP 서버: 목록 HTML + 상세): 인자 없음 → 목록 20개·`total`; `index=2` → 두 번째 상세와 `picked`; `match` 일치·불일치(`no_match` + 목록);
  목록 순서가 바뀌어도 `index` 가 새 순서를 따름; 세션 만료 → 다시 로그인 후 성공.
- 등록: 검증 전 거부, 쓰기 단계 남으면 거부, 브라우저 단계 거부, 확정+등록 한 번에, 다시 등록하면 같은 도구 갱신, 단계 사본에 원문 응답·가린 값 없음.
- 레코더 회귀: 검증 엔진을 옮긴 뒤 레코더 시험 전부 통과.
- 게이트웨이·배포: `run_tool` 로 업무 도구 호출, 배포 스냅샷에 `flow` 포함, 배포한 MCP 서버에서 `tools/call` 로 목록·상세 호출(로컬 서버 대상).
- 화면(브라우저): 검토 화면 버튼 막힘과 이유, 등록 뒤 [변환 스튜디오 열기], 스튜디오 단계 흐름·안내 띠, 테스트 실행 단계별 기록.
- 실사이트 시연(시험 아님): 네이버 기록 → 확정하고 등록 → 스튜디오 → 테스트 실행(인자 없음 → `index=2`) → 배포 → MCP 호출. 화면에 띄워 영상으로 남긴다.

## 7. 알려진 한계

- 조회 업무만. 쓰기 업무 도구는 배포 서버 승인(HITL)을 먼저 만든다.
- 고르는 지점은 하나. 결과 목록과 순위 목록이 같은 모양으로 한 부모 아래 있으면 하나의 목록으로 센다(업무 기록 4판의 한계 그대로).
- 목록이 자바스크립트로만 그려지는 화면(응답 HTML 에 링크가 없는 단일 페이지 앱)은 기록 단계에서 이미 연결되지 않으므로 업무 도구도 고르기 인자가 없다.
- 행 글자는 가린 사본이다. 개인정보처럼 보이는 글자는 가려져 `match` 로 찾을 수 없다.
