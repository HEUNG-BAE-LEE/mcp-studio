# 녹화 지시서 — 대회 제출 영상

`docs/demo-script.md` 15장면을 **클립 15개로 따로** 찍는다. 대본이 무엇을 보여줄지를
정하고, 이 문서는 **어떻게 찍을지**를 정한다. 내레이션은 `docs/narration.md`.

> **목표 초는 아직 추정이다.** 원고 음절 수(4.8음절/초) 기준이다. MiniMax 음성이 나오면
> `ffprobe` 로 재서 갱신한다. 그래서 **클립은 목표보다 넉넉히 찍는다** — 남는 걸 자르는
> 편이 부족한 걸 늘리는 것보다 훨씬 쉽다.

---

## 1. 왜 통짜로 찍지 않는가

한 번에 3분을 찍으면 장면 하나가 어긋날 때 전체를 다시 찍어야 한다. 실패 확률이 가장
높은 구간이 **외부 의존**(포털 응답)과 **수동 조작**(확장)에 몰려 있는데, 그 둘이
15장면 중 4개다. 나머지 11개를 함께 잃을 이유가 없다.

내레이션도 장면별 파일(`s01.mp3` … `s15.mp3`)이다. **화면도 같은 단위로 두면 결합이
일대일이 되고, 한 장면만 다시 찍어 갈아끼울 수 있다.**

## 2. 녹화 전에 (한 번만)

### 2-1. 포트

```bash
lsof -ti tcp:8000 -sTCP:LISTEN     # 비어 있어야 한다
```

`-sTCP:LISTEN` 을 **반드시** 붙인다. 없으면 8000번에 *접속한* 프로세스까지 잡히는데
관리자 화면을 열어 둔 Chrome 이 거기 포함된다(실측 3개 중 2개가 Chrome).

다른 프로젝트(Biz-RAG)가 이 포트를 쓴 적이 있다. `apps/admin/src/api/client.ts` 가
`:5173` 일 때 백엔드를 `:8000` 으로 못박아 두었으므로, 그 상태면 화면이 401 만 받는다.

### 2-2. DB 리셋과 기동

```bash
rm -f apps/backend/data/dev.db
cd apps/backend && .venv/bin/uvicorn app.main:app --port 8000
cd apps/admin && npm run dev
```

**리셋 직후 상태**(실측): 프로젝트 3개 · MCP 1개 · 포털 명세 세션 1개.

### 2-3. 인증키

`apps/backend/.env` 를 채우고 백엔드를 재시작하면 `seed_credentials()` 가 프로젝트마다
자동으로 채운다. **`.env` 를 화면에 띄우지 않는다** — Azure 키가 들어 있다.

### 2-4. 프로젝트를 미리 만든다 (녹화하지 않음)

관리자 `/` 에서 **`사택 지원 에이전트`** 를 만든다. 이름을 한 글자도 다르게 쓰면
장면 11(합류)이 성립하지 않는다.

장면 5~8 이 이 프로젝트를 열어 수집하므로 **녹화 전에 있어야 한다.** 만드는 과정은
찍지 않는다 — 어느 장면의 내레이션도 그걸 설명하지 않는다.

### 2-5. 브라우저를 정리한다

| 할 일 | 왜 |
|---|---|
| 방해금지 모드 켜기 | 알림 배너가 화면 위로 뜬다 |
| 북마크바 숨기기 (`Cmd+Shift+B`) | 개인 북마크가 찍힌다 |
| 필요한 탭만 남긴다 | 다른 탭 제목이 읽힌다 |
| 확장 아이콘 외 정리 | 낯선 아이콘이 시선을 끈다 |

**주소창은 가리지 않는다.** 장면 1~2 에서 `data.go.kr` 주소가 보이는 것이
"실제 포털"이라는 증거다.

### 2-6. 열어 둘 탭

| 탭 | 주소 | 쓰는 장면 |
|---|---|---|
| 1 | `https://www.data.go.kr/tcs/dss/selectDataSetList.do?dType=API&keyword=대기질` | 1 |
| 2 | `https://www.data.go.kr/data/15073861/openapi.do` | 2 |
| 3 | `http://localhost:5173/` | 3~8, 11~15 |
| 4 | `https://rt.molit.go.kr/pt/gis/gis.do` | 9~10 |

**주소를 타이핑하는 장면은 찍지 않는다.** 탭 이동은 편집으로 잘라낸다.

## 3. 녹화 규약

### 3-1. 도구와 범위

`Cmd+Shift+5` → **선택한 창** → Chrome 창. **마이크는 끈다** (음성은 MiniMax 로 따로).

**창 크기를 1440×900 으로 고정한다.** 장면마다 크기가 다르면 편집에서 확대율이 튄다.
Playwright 로 구동하는 장면은 내가 `browser_resize` 로 맞춘다.

### 3-2. 파일 이름

```
docs/recording/r01.mov … r15.mov
```

음성 `s01.mp3` … `s15.mp3` 와 번호가 맞는다. **이 규약을 전제로 결합 스크립트를 쓴다.**
다시 찍으면 같은 이름으로 덮어쓴다 — `r05_2.mov` 같은 이름을 만들면 어느 게 최종인지
알 수 없게 된다.

### 3-3. 클립 길이

```
앞 1초 (정지 화면) + 목표 초 + 뒤 2초 (정지 화면)
```

**앞뒤 정지 화면이 편집의 여유다.** 음성 길이가 갱신되면 그 안에서 잘라 맞춘다.
마우스를 움직이지 않은 채 1초를 세고 시작, 조작이 끝나면 2초를 세고 정지한다.

### 3-4. 조작 규칙

- **커서를 목적지로 곧게 움직인다.** 헤매는 커서는 편집으로 못 고친다
- **스크롤은 한 번에, 천천히.** 되돌아오는 스크롤은 찍지 않는다
- **드래그·지도 확대를 쓰지 않는다** (장면 9 는 특히 — §5 참조)
- 로딩 대기는 그대로 둔다. 편집에서 자른다

## 4. 촬영 순서 — 장면 순서와 다르다

**데이터 의존이 있기 때문이다.** 장면 11(합류)은 세 방식이 다 수집된 뒤에만 성립하고,
장면 12는 트래픽 세션이 있어야 한다.

```
1차   장면 5 → 6 → 7 → 8       포털·문서 수집   (내가 구동)
      ↓ 수집 완료 대기 (약 19초)
2차   장면 9 → 10               트래픽 기록      (당신이 수동)
3차   장면 11 → 12 → 13 → 14 → 15               (내가 구동)
4차   장면 1 → 2 → 3 → 4        문제·방법        (내가 구동)
```

**1~4 를 마지막에 찍는 이유:** 데이터 의존이 없고, 장면 3(프로젝트 목록)은 수집이 끝난
뒤에 찍어야 **카드에 배지 셋이 붙은 상태**가 나온다. 도입에서 결론을 미리 보여주는
셈이지만, 배지는 아직 설명되지 않은 기호라 스포일러가 아니다.

**2차와 3차 사이에 리셋하지 않는다.** 리셋하면 1차의 수집이 다 사라진다.

## 5. 손으로 찍는 장면 — 9, 10

확장을 Playwright 로 못 띄운다(`--load-extension` + persistent context 를 MCP 서버가
열어 주지 않는다). **이 두 장면만 당신이 실제 Chrome 에서 조작한다.**

### 장면 9 — 트래픽 기록 (14초)

**이 순서를 지켜야 의미 있는 API 가 잡힌다.**

1. 확장 아이콘 → 프로젝트 이름 **`사택 지원 에이전트`** → **기록 시작**
2. 왼쪽 위 검색줄의 **읍면동 칸**을 눌러 선택 창을 연다
3. `시도명` **서울특별시** → `시군구명` **종로구** → `읍면동명` **명륜1가**
4. **검색 아이콘** 클릭 → 단지목록 7건이 뜬다 (`ptDanjiList.do`)
5. 목록에서 **리치캐슬아파트** 클릭 → 실거래 표가 뜬다 (`ptDtl.do`)
6. **기록 종료 및 전송**

**지도를 드래그하거나 확대하지 않는다.** 드래그로 생긴 요청은 `interactionId` 가
`null` 이 되어 클릭과 묶이지 않는다 — 화면에는 오류 없이 후보에서 빠질 뿐이다.

**프로젝트 이름을 확장에 직접 입력한다.** 이미 §2-4 에서 만들었으므로 같은 이름을 쓰면
그 프로젝트로 들어간다(get-or-create).

### 장면 10 — 후보 점수 (8초)

**기록 종료 및 전송** 직후 사이드 패널에 후보가 뜬다 → **관리자에서 열기**.

`accesLog.do` 가 맨 아래에 있는 것을 보여준다. **행을 순서로 지목하지 않는다** —
`getMarker.do` 와 `getCenterLedCdPnu.do` 가 동점이라 위쪽 순서가 고정되지 않는다.
URL 로 지목한다.

## 6. 장면별 지시

`구동` — **PW**: 내가 Playwright 로 구동한다. **손**: 당신이 조작한다.

내가 구동하는 장면은 **"장면 N 시작"** 이라고 말하면 그 조작을 순서대로 실행하고
끝에서 멈춘다. 당신은 녹화 시작·정지만 누른다.

### 장면 1 — 문제, 수천 개 · 10초 · PW

| | |
|---|---|
| 시작 프레임 | 탭 1, 검색 결과 목록 상단 |
| 조작 | 없음. 목록이 보이는 위치에서 정지 |
| 끝 프레임 | 같은 화면 |
| 확인 | 결과가 여러 페이지에 걸쳐 있다. **기관 이름이 제각각**인 것도 보인다 |

내레이션이 "수천 개"와 "기관마다 다르다"를 말한다. **둘 다 이 화면에 있다.**

### 장면 2 — 문제, 사람이 읽는 표 · 12초 · PW

| | |
|---|---|
| 시작 프레임 | 탭 2, 오픈API 상세페이지 상단 |
| 조작 | **요청변수 표**가 보이는 위치까지 한 번에 스크롤 |
| 끝 프레임 | `요청주소` 와 `요청변수` 표가 함께 보이는 화면 |
| 확인 | **HTML 표**다. 기계가 읽을 형식이 아니라는 게 눈으로 보인다 |

이 화면이 장면 5(자연어로 찾기)의 전제다. 그 표를 우리가 파싱한다.

### 장면 3 — 통합 선언 · 10초 · PW

| | |
|---|---|
| 시작 프레임 | 탭 3, 프로젝트 목록 |
| 조작 | 없음 |
| 끝 프레임 | 같은 화면 |
| 확인 | **`사택 지원 에이전트` 카드에 배지 셋.** 리셋 후 남은 세 프로젝트 이름에 테스트 흔적이 없는지 |

검정 화면으로 넘어오는 첫 장면이다. **외부 포털 → 우리 도구의 전환점**이다.

### 장면 4 — 방법 셋 · 12초 · PW

| | |
|---|---|
| 시작 프레임 | 왼쪽 레일 **수집 방식 안내** 클릭 직후 |
| 조작 | 카드 셋이 한 화면에 들어오는 위치로 |
| 끝 프레임 | 세 카드 + 배지 셋 |
| 확인 | 아래 표대로면 정상이다 |

배지가 셋 다 같은 문구가 **아니다.** 이걸 실패로 오판하지 않는다:

| 카드 | 배지 |
|---|---|
| 트래픽 기반 수집 | `사용 가능` |
| 포털 공개 기반 수집 | **`1 / 4 사용 가능`** — 기관 포털 4곳 중 1곳만 동작한다 |
| 문서 기반 수집 | `사용 가능` |

**포털 카드 안의 기관 목록에 `준비중` 셋이 보이는 것도 정상이다**(KOSIS · 서울 열린데이터
광장 · 기상청 API허브). 되는 것만 되는 척하지 않는 화면이라 오히려 보여줄 값이 있다.
내레이션은 이 숫자를 말하지 않으므로 화면과 어긋나지 않는다.

### 장면 5 — ①포털, 자연어로 찾기 · 22초 · PW ★

| | |
|---|---|
| 시작 프레임 | 프로젝트 열기 → `+ 수집 시작` 팝업 |
| 조작 | **포털 공개 기반** → 용도란에 `지역별 대기질과 미세먼지를 알려주는 API 가 필요해` → **API 찾기** |
| 끝 프레임 | 후보 목록. 체크된 것과 이유 한 줄씩 |
| 실제 소요 | **약 18초** (후보 30개 중 17개 자동 체크) |
| 확인 | 검색어가 용도에서 뽑혀 **바뀐다.** 고른 이유·뺀 이유가 후보마다 한 줄 |

**대기 18초가 목표 22초를 거의 채운다.** 로딩이 곧 내용인 장면이다 — 자르지 않는다.

### 장면 6 — ①포털, 수집 · 8초 · PW

| | |
|---|---|
| 시작 프레임 | 장면 5 의 후보 목록 |
| 조작 | **6개만 남기고** → **수집 시작** → 진행현황으로 자동 이동 |
| 끝 프레임 | **04 수집 진행현황**, 진행률이 도는 화면 |
| 확인 | **완료를 기다리지 않는다.** 8초 안에 "시작됐다"까지만 |

**반드시 10개 이하로 고른다.** 6개면 19초에 오퍼레이션 7개, 30개면 92초다(실측).

완료 화면은 찍지 않는다 — 결과는 **장면 11 의 `게시 수집` 탭 배지**가 증명한다.
내레이션도 "창을 닫아도 계속됩니다"라고 말하므로 앞뒤가 맞는다.

**이 클립을 찍은 뒤 약 19초를 기다린다.** 수집이 끝나야 장면 11 이 성립한다.

문서 탭은 **2건**이다(성공 1 + 0개 1). 0개 세션도 수집 사건이라 세어진다 — 정상이다.

### 장면 12 — MCP 만들기 · 8초 · PW

## 7. 실패 판정 — 다시 찍을 것과 넘어갈 것

| 증상 | 판정 |
|---|---|
| 장면 11 의 탭 하나가 **0** | **다시 찍는다.** 구조적 결론이 무너진다 |
| 장면 14 의 호출 로그가 **1건** | **다시 찍는다.** 한 질문에 담겼거나 상한에 걸렸다 |
| 장면 8 의 **서비스명이 안 보인다** | **다시 찍는다.** 내레이션의 근거가 화면에 없다 |
| 장면 9 에서 클릭이 **0건** | **다시 찍는다.** §7-1 참조 |
| 커서가 헤맸다 | 넘어간다. 1~2초는 편집으로 잘린다 |
| 로딩이 예상보다 길었다 | 넘어간다. 자르면 된다 |
| 클립이 목표보다 짧다 | **다시 찍는다.** 늘릴 방법이 없다 |

### 7-1. 재촬영 때 리셋할 범위

| 다시 찍을 장면 | 리셋 |
|---|---|
| 9~10 (트래픽) | **필수** — 세션 번호가 밀리고 중복 도구가 생긴다. **1차부터 다시** |
| 5~6 (포털) | 불필요. 같은 URL 로 다시 수집하면 **직전 세션에 누적**된다(설계) |
| 7~8 (문서) | 불필요. 같은 PDF 를 다시 올리면 세션이 하나 더 생긴다 |
| 1~4, 11~15 | 불필요 |

**리셋했으면 확장도 새로고침하고 대상 페이지도 새로고침한다.** 이미 열려 있던 탭의
스크립트는 고아가 되어 클릭이 하나도 안 잡히는데, **화면에는 오류 없이 "0 클릭"만
보인다.** 장면 9 가 실패하는 가장 흔한 이유다.

## 8. 다 찍은 뒤

```bash
ls -l docs/recording/          # r01.mov … r15.mov 15개
ffprobe -v error -show_entries format=duration -of csv=p=0 docs/recording/r*.mov
```

알려 주면 내가 한다:

1. 음성 15개(`s01.mp3`…)와 클립 15개의 **실제 길이를 재서** 표로 맞춘다
2. 클립이 음성보다 짧은 장면을 찾아 **다시 찍을 목록**을 준다
3. `ffmpeg` 로 클립을 음성 길이에 맞추고, 자막을 얹고, 15개를 잇는다

`ffmpeg` 이 아직 없다. **`brew install ffmpeg` 이 3번의 전제다.**
