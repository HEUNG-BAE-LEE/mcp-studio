# 촬영 대본 — 대회 제출 영상 (3분)

중간결과보고서 §6.4 규격: **3분 이내**, 유튜브 일부공개.

**이 대본은 2026-07-30 dev(`cc4092c`) 기준이다.** 검정 테마·사이드바 6항목·화면 문구 `MCP`.

---

## 이 영상의 설계

심사위원은 영상을 여러 편 연달아 본다. **처음 20초에 문제가 안 잡히면 뒤가 다 흐려진다.**
그래서 구조를 이렇게 잡았다.

```
① 문제와 목표        ─ 왜 이걸 만들었나
② 수집 엔진 셋 소개   ─ 우리의 차별점을 한 화면에
③ 엔진 하나씩 예시    ─ 트래픽 → 포털 → 문서
④ 하나로 합류 + 실행  ─ 세 경로로 모은 도구를 사람 말로 부른다
⑤ 마무리
```

**핵심은 ④다.** 세 엔진이 **같은 프로젝트로** 모이게 찍으면, 마지막 Playground 에
세 경로에서 온 도구가 함께 뜬다. 보고서 §2.1 의 주장("어느 경로로 모았든 이후 도구
변환·실행은 같다")이 말이 아니라 화면으로 증명된다.

경로별로 각각 완주시키면 실행 장면이 흩어져 그 증명이 사라진다. **실행은 한 번만,
맨 마지막에** 둔다.

## 0. 촬영 전 준비

### 0-1. DB 리셋 (매 테이크)

```bash
rm -f apps/backend/data/dev.db
lsof -ti tcp:8000 -sTCP:LISTEN | xargs kill
cd apps/backend && .venv/bin/uvicorn app.main:app --port 8000
```

`-sTCP:LISTEN` 을 **반드시** 붙인다. 없으면 8000번에 *접속한* 프로세스까지 잡히는데
관리자 화면을 열어 둔 Chrome 이 거기 포함된다(실측 3개 중 2개가 Chrome). 브라우저가 통째로 닫힌다.

**리셋 직후 상태** (2026-07-30 실측):

| 항목 | 값 |
|---|---|
| 프로젝트 | 3개 — `국토교통부 실거래가`(#1) / `국가통계포털 KOSIS`(#2) / `공공데이터포털 오픈API`(#3) |
| MCP 도구 | 1개 — `search_apartment_markers` (프로젝트 #1) |
| 세션 | 1개 — 포털 명세 세션 (프로젝트 #3) |

**리셋을 건너뛰면 번호가 밀린다.** 리허설 중 프로젝트를 만들면 장면 주소가 다른 곳을 가리킨다.

### 0-2. 포트 — 촬영 전에 반드시 확인

`apps/admin/src/api/client.ts` 가 `:5173` 일 때 백엔드를 **`:8000`** 으로 못박아 두었다.

```bash
lsof -ti tcp:8000 -sTCP:LISTEN   # 비어 있어야 한다
```

**다른 프로젝트(Biz-RAG)가 이 포트를 쓴 적이 있다.** 그 상태로는 관리자 화면이 401 만 받는다.
촬영 전에 내려 둔다.

### 0-3. 인증키

`.env` 를 채우고 백엔드를 재시작하면 `seed_credentials()` 가 프로젝트마다 자동으로 채운다.

| 환경변수 | 어느 장면 |
|---|---|
| `JUSO_CONFM_KEY` | 엔진② 포털 — 도로명주소 API |
| `DATA_GO_KR_SERVICE_KEY` | 엔진③ 문서 — 기상청 (실행은 안 함) |

**키가 있어도 API 마다 활용신청 승인이 따로 필요하다.** 같은 키로 에어코리아 예보는
401 이 났다(실측). **쓸 API 를 촬영 전에 한 번 호출해 승인을 확인한다.**

### 0-4. 미리 열어 둘 탭

| 탭 | 주소 |
|---|---|
| 1 | `http://localhost:5173/` |
| 2 | `https://rt.molit.go.kr/pt/gis/gis.do` |

탭 이동과 로딩은 편집으로 잘라낸다. **주소를 타이핑하는 장면은 넣지 않는다.**

### 0-5. 이 영상이 쓰는 프로젝트 하나

세 엔진이 **한 프로젝트로** 모여야 마지막 장면이 성립한다. 이름을 **`공공 API 에이전트`** 로 정한다.

- 엔진① 확장 사이드 패널의 프로젝트 이름란에 **이 이름을 그대로** 입력한다
- 엔진②③ 은 그 프로젝트를 열고 `+ 수집 시작` 으로 진행한다

한 글자라도 다르면 다른 프로젝트가 생겨 마지막 도구 목록이 쪼개진다.

## Playwright 구동 가이드

### 확장은 Playwright 로 못 띄운다

Chrome 확장은 `--load-extension` 과 persistent context 가 필요한데 MCP playwright 서버가
그 옵션을 열어 주지 않는다. **장면 4~5(트래픽 기록)는 실제 Chrome 에서 손으로 해야 한다.**

나머지 장면은 전부 Playwright 로 구동할 수 있다.

### 권하는 방식 — 내가 몰고, 당신이 녹화한다

화면 조작을 손으로 하면 커서가 헤매고 타이핑 속도가 들쭉날쭉해진다. 대신:

1. `Cmd+Shift+5` 로 **Playwright 브라우저 창**을 녹화 대상으로 잡는다
2. "장면 7 시작" 처럼 말해 주면 내가 그 장면의 조작을 순서대로 실행한다
3. 각 장면 끝에서 멈추고 다음 지시를 기다린다

**커서 이동이 일정하고, 장면 경계가 깨끗하고, 다시 찍을 때 같은 동작이 재현된다.**
내레이션 길이에 맞춰 대기 시간도 조절할 수 있다.

### 장면별 구동 순서

| # | 구동 내용 |
|---|---|
| 2 | `navigate http://localhost:5173/` |
| 3 | 레일의 **수집 방식 안내** 클릭 → 카드 셋이 보이는 위치에서 정지 |
| 6 | 세션 상세에서 `getMarker.do` 행의 **MCP 만들기** → 편집 화면 |
| 7 | 프로젝트 → `+ 수집 시작` → **포털 공개 기반** → 용도란 입력 → **API 찾기** → 결과 대기 |
| 8 | 체크 6개만 남기기 → **수집 시작** → 진행현황 자동 이동 → 완료 대기 → **MCP 조회하기** |
| 9 | `+ 수집 시작` → **문서 기반** → `browser_file_upload` → 결과 대기 |
| 10 | 같은 자리에서 보도자료 업로드 → 결과 대기 |
| 11 | **05 MCP 조회하기** → 목록 전체가 보이는 위치 |
| 12 | **06 Playground** → 질의 입력 → 실행 결과 대기 |
| 13 | `navigate http://localhost:5173/` |

**뷰포트는 1440×900 으로 고정한다.** 장면마다 창 크기가 달라지면 편집에서 티가 난다.

### 파일 업로드

장면 9~10 은 드래그앤드롭 대신 `browser_file_upload` 로 넣는다. 화면에는 **찾아보기** 를
누른 것과 같은 결과가 나온다. 드래그 궤적을 보여주고 싶으면 그 장면만 손으로 한다.

## 대사에서 쓰지 말아야 할 말

`#33` 에서 화면 문구가 `액션` → `MCP` 로 바뀌었다.

| 쓰지 않는다 | 지금 이름 |
|---|---|
| 액션 | **MCP 도구** |
| 테스트 콘솔 | **Playground** |
| 수집 세션 | **수집현황** |
| 수집 엔진 | **수집 방식 안내** (왼쪽 레일 아이콘) |

**약속하지 않는 것 셋** — 실측이 흔들린다.

1. **소요 시간.** LLM 요약이 전체를 지배하고 편차가 크다(152ms ~ 5,380ms)
2. **후보 순위.** `getMarker.do` 와 `getCenterLedCdPnu.do` 가 동점이라 순서가 안 고정된다
3. **버튼 활성 여부.** `MCP 만들기` 의 비활성 조건은 점수가 아니라 응답이 JSON 이 아닐 때다

## 실패하면

**포털이 바뀌어 장면 7~8 이 안 되면** 그 구간을 빼고 장면 9~10(문서)을 늘린다.
문서 경로는 저장소 안의 PDF 만 쓰므로 외부 변수가 없다. 그때 장면 11 대사를
"두 경로로 모은 것이" 로 줄인다.

**인증키 승인이 안 되어 있으면** 장면 12 는 그대로 진행한다 — 트래픽으로 만든
`getMarker.do` 는 키가 필요 없다. 이 대본이 이미 그 도구로 실행하게 되어 있다.
