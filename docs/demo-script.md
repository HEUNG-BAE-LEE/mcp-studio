# 촬영 대본 — 대회 제출 영상 (3분)

중간결과보고서 §6.4 규격: **3분 이내**, 유튜브 일부공개.

**2026-07-30 dev(`cc4092c`) 기준.** 검정 테마·사이드바 6항목·화면 문구 `MCP`.

---

## 이 영상의 설계

심사위원은 영상을 여러 편 연달아 본다. **처음 20초에 문제가 안 잡히면 뒤가 다 흐려진다.**

```
① 문제와 목표         왜 만들었나
② 수집 엔진 셋 소개    차별점을 한 화면에
③ 엔진별 예시         포털 → 문서 → 트래픽
④ 합류               한 프로젝트에 세 방식이 모인 화면
⑤ 실행               사람 말로 부르고, 도구가 이어서 불린다
⑥ 마무리
```

**④와 ⑤가 이 영상의 결론이다.** 세 엔진이 **한 프로젝트로** 모이면 `수집현황` 의 탭 셋에
각각 건수가 붙는다. 그 위에서 Playground 가 도구를 이어 부른다. 보고서 §2.1 의 주장
("어느 경로로 모았든 이후 도구 변환·실행은 같다")이 말이 아니라 화면이 된다.

**실행을 경로마다 넣지 않는다.** 흩어지면 이 증명이 사라진다.

### 시나리오 — 누가 이걸 쓰나

> **사내 시스템과 공공 데이터를 함께 쓰는 기업 총무 AI 비서.**
> 직원 사택 후보지를 알아보는 상황이다.

| 무엇을 묻나 | 쓰는 도구 | 어느 엔진 |
|---|---|---|
| 후보 동네에 어떤 아파트가 있나 | 단지 목록 조회 | 트래픽 |
| 그 단지가 얼마에 거래됐나 | 실거래 내역 조회 | 트래픽 |
| 그 동네 공기는 어떤가 | 대기질 조회 | 포털 |
| 사내 회의실 예약 현황 | 회의실 예약 API | 문서 |

세 개를 한 주제로 억지로 묶지 않는다. **요점은 출처가 다른 API 가 한 도구 풀로 합류한다는
것이다.** 공공(트래픽·포털)과 사내(문서)가 섞이는 것이 보고서 §7.1 의 B2G·B2B 두 시장을
한 화면에서 보여준다. "공공데이터 전용 도구"로 보이면 시장이 절반으로 줄어든다.

## 0. 촬영 전 준비

### 0-1. DB 리셋 (매 테이크)

```bash
rm -f apps/backend/data/dev.db
lsof -ti tcp:8000 -sTCP:LISTEN | xargs kill
cd apps/backend && .venv/bin/uvicorn app.main:app --port 8000
```

`-sTCP:LISTEN` 을 **반드시** 붙인다. 없으면 8000번에 *접속한* 프로세스까지 잡히는데
관리자 화면을 열어 둔 Chrome 이 거기 포함된다(실측 3개 중 2개가 Chrome).

**리셋 직후 상태** (실측):

| 항목 | 값 |
|---|---|
| 프로젝트 | 3개 — `국토교통부 실거래가`(#1) / `국가통계포털 KOSIS`(#2) / `공공데이터포털 오픈API`(#3) |
| MCP 도구 | 1개 (프로젝트 #1) |
| 세션 | 1개 — 포털 명세 세션 (프로젝트 #3) |

### 0-2. 포트 — 촬영 전에 반드시 확인

`apps/admin/src/api/client.ts` 가 `:5173` 일 때 백엔드를 **`:8000`** 으로 못박아 두었다.

```bash
lsof -ti tcp:8000 -sTCP:LISTEN   # 비어 있어야 한다
```

다른 프로젝트(Biz-RAG)가 이 포트를 쓴 적이 있다. 그 상태면 관리자 화면이 401 만 받는다.

### 0-3. 인증키

`.env` 를 채우고 백엔드를 재시작하면 `seed_credentials()` 가 프로젝트마다 자동으로 채운다.

**키가 있어도 API 마다 활용신청 승인이 따로 필요하다.** 같은 키로 에어코리아 예보는
401 이 났다(실측). **그래서 이 대본은 실행을 트래픽 도구로만 한다** — 국토교통부
실거래가는 인증키가 필요 없다. 포털·문서 도구는 목록에 올리는 데까지만 쓴다.

### 0-4. 프로젝트 하나로 모은다

이름을 **`사택 지원 에이전트`** 로 정한다.

- 엔진③ 확장 사이드 패널의 프로젝트 이름란에 **이 이름을 그대로** 입력한다
- 엔진①② 는 그 프로젝트를 열고 `+ 수집 시작` 으로 진행한다

한 글자라도 다르면 다른 프로젝트가 생겨 ④ 합류 장면이 성립하지 않는다.

### 0-5. 미리 열어 둘 탭

| 탭 | 주소 |
|---|---|
| 1 | `http://localhost:5173/` |
| 2 | `https://rt.molit.go.kr/pt/gis/gis.do` |

탭 이동과 로딩은 편집으로 잘라낸다. **주소를 타이핑하는 장면은 넣지 않는다.**

## 검증에서 나온 제약 — 대사와 조작에 반영해야 한다

### 1. 질의를 두 턴으로 나눈다 (필수)

목록과 실거래를 **한 질문에 넣으면 실패한다.** LLM 이 목록 조회를 반복하다 도구 호출
상한(`MAX_TOOL_CALLS = 3`)에 걸려 실거래에 도달하지 못한다(실측 2회 재현).

```
턴 1   "종로구 명륜1가에 어떤 아파트가 있어?"        도구 1회
턴 2   "리치캐슬아파트 2025년 실거래가 알려줘"       도구 2회 ★
```

턴 2 가 하이라이트다. **LLM 이 단지코드를 모르니 목록을 먼저 부르고, 거기서 `248205` 를
뽑아 실거래를 조회한다.** 사슬이 호출 로그에 두 줄로 남는다.

상한을 올려 한 질문에 담고 싶은 유혹이 있지만 **하지 않는다.** 그 상수에는
"공공 API 는 호출 간격 1초를 지키므로 사용자가 그만큼 기다리고 인증키 쿼터도 그만큼
나간다"는 근거가 붙어 있다. 시연을 위해 제품 판단을 흔들지 않는다.

### 2. 응답은 "구조 + 샘플 1건"으로 LLM 에게 간다

`summarize_response()` 가 그렇게 줄인다. 그래서 턴 1 답변에 단지가 **1개만** 나온다.
API 는 7건을 주고 `totCnt: 7` 도 전달되지만, 목록 전체가 펼쳐지지는 않는다.

**버그가 아니라 보고서 §3.3.4 의 데이터 최소 보존 원칙이다.** 대사로 짚으면 오히려 강하다.

> "응답 원문은 저장하지 않습니다. 구조와 샘플 한 건만 남겨 넘깁니다.
>  총 7건이라는 건수는 그대로 전달되니, 필요하면 다음 질문으로 이어갑니다."

### 3. 단지를 지정해야 거래가 나온다

목록 첫 단지 `건양하늘터` 는 **거래가 없다**(실측). 거래가 있는 곳:

| 단지 | 단지코드 | 거래 |
|---|---|---|
| **리치캐슬아파트** | `248205` | **2025-10-15 · 84.33㎡ · 65,000만원 · 2층** ← 촬영에 쓴다 |
| 방산아파트 | `600224` | 2025년 · 32.53㎡ · 19,500만원 |
| 송림아마레스아파트 | `248204` | 2024년 · 75.62㎡ · 57,400만원 |
| 건양하늘터 · 아미레스아파트 | — | 거래 없음 |

**2026년으로 조회하면 빈 결과가 온다.** 질의에 `2025년` 을 명시한다.

### 4. 문서로 만든 도구는 실행하지 않는다

사내 회의실예약 API 의 엔드포인트는 사내망 주소다. 호출하면 실패한다.
**목록에 올리는 데까지만** 보여주고 대사로 밝힌다.

> "사내 시스템 명세서도 같은 방식으로 도구가 됩니다.
>  이 도구는 사내망에서만 호출되므로 여기서는 목록에만 올려 둡니다."

## Playwright 구동 가이드

### 확장은 Playwright 로 못 띄운다

`--load-extension` 과 persistent context 가 필요한데 MCP playwright 서버가 그 옵션을
열어 주지 않는다. **장면 8~9(트래픽 기록)는 실제 Chrome 에서 손으로 한다.**
나머지 12개는 전부 자동 구동할 수 있다.

### 권하는 방식 — 내가 몰고, 당신이 녹화한다

1. `Cmd+Shift+5` 로 **Playwright 브라우저 창**을 녹화 대상으로 잡는다
2. "장면 4 시작" 처럼 말하면 내가 그 장면 조작을 순서대로 실행한다
3. 각 장면 끝에서 멈추고 다음 지시를 기다린다

**커서 이동이 일정하고, 장면 경계가 깨끗하고, 다시 찍을 때 같은 동작이 재현된다.**
**뷰포트는 1440×900 으로 고정한다.**

### 장면별 구동 순서

| # | 구동 |
|---|---|
| 2 | `navigate http://localhost:5173/` |
| 3 | 레일 **수집 방식 안내** → 카드 셋이 보이는 위치 |
| 4 | 프로젝트 → `+ 수집 시작` → **포털 공개 기반** → 용도란 입력 → **API 찾기** → 결과 대기 |
| 5 | 체크 6개만 남기기 → **수집 시작** → 진행현황 자동 이동 → 완료 대기 |
| 6 | `+ 수집 시작` → **문서 기반** → `browser_file_upload` → 결과 대기 |
| 7 | 같은 자리에서 보도자료 업로드 → 결과 대기 |
| 10 | **03 수집현황** → 탭 셋이 다 보이는 위치 |

### 장면 8 의 수동 조작 순서

확장이 필요해 손으로 한다. **이 순서를 지켜야 의미 있는 API 가 잡힌다.**

1. 확장 아이콘 → 프로젝트 이름 `사택 지원 에이전트` → **기록 시작**
2. 왼쪽 위 검색줄의 **읍면동 칸**을 눌러 선택 창을 연다
3. `시도명` **서울특별시** → `시군구명` **종로구** → `읍면동명` **명륜1가**
4. **검색 아이콘** 클릭 → 단지목록 7건이 뜬다 (`ptDanjiList.do`)
5. 목록에서 **리치캐슬아파트** 클릭 → 실거래 표가 뜬다 (`ptDtl.do`)
6. **기록 종료 및 전송**

**지도를 드래그하거나 확대하지 않는다.** 드래그로 생긴 요청은 `interactionId` 가
`null` 이 되어 클릭과 묶이지 않는다.

**약속하지 않는 것 셋** — 실측이 흔들린다.

1. **소요 시간.** LLM 요약이 전체를 지배하고 편차가 크다(152ms ~ 5,380ms)
2. **후보 순위.** `getMarker.do` 와 `getCenterLedCdPnu.do` 가 동점이라 순서가 안 고정된다
3. **버튼 활성 여부.** `MCP 만들기` 의 비활성 조건은 점수가 아니라 응답이 JSON 이 아닐 때다

## 재촬영 체크리스트

| 다시 찍을 장면 | 되돌릴 범위 |

스크립트는 고아가 되어 클릭이 하나도 안 잡히는데, 화면에는 오류 없이 "0 클릭"만 보인다.

## 실패하면

**포털이 바뀌어 장면 4~5 가 안 되면** 그 구간을 빼고 장면 6~7(문서)을 늘린다.
문서 경로는 저장소 안의 PDF 만 쓰므로 외부 변수가 없다.

**장면 8 에서 단지목록이 안 뜨면** 연도 칸이 `2026년` 인지 확인한다. 2026년 기준으로
명륜1가에 단지 7건이 잡히는 것을 실측했다.

**장면 13 에서 거래가 안 나오면** 연도를 확인한다. 2026년에는 거래가 없고 **2025년**에 있다.
