# 내레이션 원고 — 제출 영상 (MiniMax TTS 용)

`docs/demo-script.md` 의 장면 15개에 1:1 대응한다. **장면 번호가 그 대본과 같다.**

## 이 원고의 구조

```
1~2   문제 — 공공 API 가 제각각이라는 사실
3     통합 선언 — 하나의 규격으로 모은다
4     방법이 셋
5~10  포털 → 문서 → 트래픽
11~12 합류 → MCP
13~14 실행. 14 가 하이라이트
15    마무리
```

**장면 1~2 는 비유를 쓰지 않는다.** 비유는 반박할 수 없지만 검증할 수도 없다. 인증키
이름이 기관마다 다르고 명세가 HTML 표라는 것은 실측이고, 뒤 장면들이 그 사실 하나하나에
답한다(장면 5 가 표를, 장면 12 가 인증키를).

**시나리오는 장면 5 앞에 한 줄로 붙인다.** 도입에서 시나리오까지 넣으면 44초로도
부족하다. 화자는 직원 사택 후보지를 알아보는 **기업 총무 AI 비서** 쪽 사람이다.

## MiniMax 에 넣기 전에

- **장면마다 따로 생성한다.** 통으로 만들면 한 문장 고칠 때 전체를 다시 만들어야 하고,
  장면별 길이를 맞출 수 없다
- 파일 이름을 `s01.mp3` … `s15.mp3` 로 `docs/narration/` 에 저장한다.
  그 이름을 전제로 결합 스크립트를 만든다
- **속도는 기본(1.0)** 으로 둔다. 목표 초는 4.8음절/초 낭독 기준이다
- 원고의 **쉼표와 마침표를 그대로 둔다.** MiniMax 가 그 자리에서 숨을 쉰다

## 읽는 방식 확인이 필요한 낱말

**한 장면을 먼저 만들어 들어 보고** 정한다. 어색하면 오른쪽 한글로 바꿔 넣는다.

| 원고 표기 | 기대 발음 | 어색하면 |
|---|---|---|
| API | 에이피아이 | `에이피아이` |
| MCP | 엠씨피 | `엠씨피` |
| AI | 에이아이 | `에이아이` |
| 명륜1가 | 명륜 일 가 | `명륜일가` |

**숫자를 원고에 넣지 않았다.** "이백 밀리초" 같은 값은 TTS 발음이 흔들리고, 대본에도
"시간을 약속하지 않는다"고 적혀 있다. 수치는 **자막과 화면**으로만 보여준다.

`XML` · `JSON` 도 원고에서 뺐다. 두 글자를 또박또박 읽히게 만들려면 발음 표기를 넣어야
하고, 그 값이 대사에서 하는 일은 "형식이 제각각"이라는 것뿐이다. **화면에는 보인다.**

## 장면 1 — 문제, 수천 개 (10초)

```
공공데이터포털에는 오픈API가 수천 개 있습니다. 그런데 인증키 이름이 기관마다 다릅니다.
```

## 장면 2 — 문제, 사람이 읽는 표 (12초)

```
응답 형식도 제각각이고, 명세는 사람이 읽는 표로만 공개됩니다. AI가 이걸 바로 쓸 수 없습니다.
```

## 장면 3 — 통합 선언 (10초)

```
저희는 제각각인 것들을 하나의 규격으로 모읍니다. 공공이든 사내든, 한 에이전트가 구분 없이 부릅니다.
```

## 장면 4 — 방법 셋 (12초)

```
모으는 방법은 셋입니다. 포털이 공개한 명세를 읽고, 문서를 올려 뽑고, 화면이 부르는 호출을 관측합니다.
```

## 장면 5 — ①포털, 자연어로 찾기 (22초)

```
직원 사택 후보지를 알아보는 상황을 예로 들겠습니다. 첫째는 포털입니다. 쓸 용도를 문장으로 적으면 시스템이 포털을 검색해 목적에 맞는 API만 골라 체크합니다. 왜 골랐고 왜 뺐는지도 한 줄씩 답합니다.
```

## 장면 6 — ①포털, 수집 (8초)

```
고른 것만 모읍니다. 수집은 서버에서 돌기 때문에 창을 닫아도 계속됩니다.
```

## 장면 7 — ②문서, 올리기 (8초)

```
둘째는 문서입니다. 사내 회의실 예약 명세서를 올렸습니다. 공공만이 아닙니다.
```

## 장면 8 — ②문서, 지어내지 않는다 (16초)

```
보도자료도 올려 봅니다. 문서를 못 읽은 게 아닙니다. 읽었지만 엔드포인트가 없어서 도구를 만들지 않았습니다. 없는 API를 지어내지 않는 쪽이 더 중요합니다.
```

## 장면 9 — ③트래픽, 기록 (14초)

```
셋째는 관측입니다. 기록을 켜고 동네를 고른 뒤 단지를 누릅니다. 그때 화면이 부른 호출이 클릭과 함께 잡힙니다. 단지 목록과 실거래 내역, 두 개입니다.
```

## 장면 10 — ③트래픽, 후보 점수 (8초)

```
실제로 데이터를 나른 호출이 위로 옵니다. 로그를 남기는 호출은 감점돼 맨 아래입니다.
```

## 장면 11 — ④합류 (12초)

```
세 방식으로 모은 것이 한 프로젝트에 쌓였습니다. 게시, 트래픽, 문서. 어느 방식으로 모았든 여기서부터는 똑같습니다.
```

## 장면 12 — MCP 만들기 (8초)

```
후보를 골라 도구로 만듭니다. 파라미터와 필수 헤더가 함께 채워집니다.
```

## 장면 13 — ⑤실행, 턴 1 (12초)

```
이제 사람 말로 부릅니다. 명륜1가에 어떤 아파트가 있는지 물었습니다. 응답 원문은 저장하지 않고 구조와 샘플만 넘깁니다.
```

## 장면 14 — ⑤실행, 턴 2 (20초) ★

```
이번에는 단지를 지정해 실거래가를 물었습니다. 단지 코드를 모르니 목록을 먼저 부르고, 거기서 코드를 찾아 실거래를 조회합니다. 도구 두 개를 스스로 이어 부른 것입니다. 사람이 알려 준 것이 아닙니다.
```

## 장면 15 — 마무리 (8초)

```
공공이든 사내든, 사람이 쓰던 화면을 AI가 부를 도구로 바꿉니다.
```

## 대사에 넣지 않은 것 — 의도적이다

| 넣지 않음 | 왜 |
|---|---|
| 소요 시간("몇 초 안에") | 실측 편차가 152ms ~ 5,380ms |
| 후보 순위("1위") | 두 API 가 동점이라 순서가 고정되지 않는다 |
| 구체적 거래 금액 | 화면에 뜨는 값을 말로 반복하면 어긋날 때 티가 난다 |
| 테스트 개수·진척도 | 보고서가 할 일이다. 영상은 동작을 보여준다 |
| 인증키 이름 넷 나열 | 화면에 보인다. 대사는 "기관마다 다르다"까지만 |

## 약점을 설계로 설명하는 두 문장

**장면 13** — "응답 원문은 저장하지 않고 구조와 샘플만 넘깁니다."

`summarize_response()` 때문에 화면에 단지가 **하나만** 보인다. 이 문장이 없으면
결함으로 읽힌다. 밝히면 보고서 §3.3.4 의 데이터 최소 보존 원칙의 증거가 된다.

**장면 8** — "읽었지만 엔드포인트가 없어서 도구를 만들지 않았습니다."

문서 수집이 0개를 낸 장면이다. 실패로 보일 자리에서 **없는 API 를 지어내지 않는다**는
설계를 말한다.

## 장면 14 의 마지막 문장

"사람이 알려 준 것이 아닙니다" 를 뒤에 붙였다. 화면의 호출 로그 두 줄만으로는
**LLM 이 스스로 이었다**는 것이 안 읽힌다 — 미리 정해 둔 순서로 보인다.
이 영상에서 가장 증명하고 싶은 것이라 말로 못 박는다.

## 음성을 만든 뒤에 할 일

1. `docs/narration/s01.mp3` … `s15.mp3` 로 저장한다
2. 알려 주면 `ffprobe` 로 **실제 길이를 재서** 장면별 목표 초를 갱신한다
3. 그 길이에 맞춘 **녹화 지시서**를 만든다
4. 장면별로 화면을 녹화한다 (장면 9~10 은 확장이 필요해 손으로, 나머지는 Playwright)
5. `ffmpeg` 로 클립을 음성 길이에 맞추고 자막을 얹는다

**2번이 중요하다.** TTS 길이는 원고 길이와 정확히 비례하지 않는다 — 실제로 재야
화면과 음성이 어긋나지 않는다.

`ffmpeg` 이 아직 없다. `brew install ffmpeg` 이 5번의 전제다.
