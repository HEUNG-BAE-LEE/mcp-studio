# 내레이션 원고 — 제출 영상 (MiniMax TTS 용)

`docs/demo-script.md` 의 장면 14개에 1:1 대응한다. **장면 번호가 그 대본과 같다.**

시나리오는 **"사내 시스템과 공공 데이터를 함께 쓰는 기업 총무 AI 비서"** — 직원 사택
후보지를 알아보는 상황이다. 원고가 그 화자의 말투를 따른다.

## MiniMax 에 넣기 전에

- **장면마다 따로 생성한다.** 통으로 만들면 한 문장 고칠 때 전체를 다시 만들어야 하고,
  장면별 길이를 맞출 수 없다
- 파일 이름을 `s01.mp3` … `s14.mp3` 로 `docs/narration/` 에 저장한다.
  그 이름을 전제로 결합 스크립트를 만든다
- **속도는 기본(1.0)** 으로 둔다. 목표 초는 4.8음절/초 낭독 기준이다
- 원고의 **쉼표와 마침표를 그대로 둔다.** MiniMax 가 그 자리에서 숨을 쉰다

## 읽는 방식 확인이 필요한 낱말

**한 장면을 먼저 만들어 들어 보고** 정한다. 어색하면 오른쪽 한글로 바꿔 넣는다.

| 원고 표기 | 기대 발음 | 어색하면 |
|---|---|---|
| API | 에이피아이 | `에이피아이` |
| MCP | 엠씨피 | `엠씨피` |
| AI | 에이아이 | `에이아이` |
| 명륜1가 | 명륜 일 가 | `명륜일가` |

**숫자를 원고에 넣지 않았다.** "이백 밀리초" 같은 값은 TTS 발음이 흔들리고, 대본에도
"시간을 약속하지 않는다"고 적혀 있다. 수치는 **자막과 화면**으로만 보여준다.

## 장면 1 — 문제 (12초)

```
직원 사택을 알아보려면 사람이 이 지도를 눌러 봐야 합니다. 화면 뒤에서 API가 데이터를 나르지만, 그 명세는 공개돼 있지 않습니다.
```

## 장면 2 — 목표 (12초)

```
저희는 사람이 쓰는 화면에서 API를 찾아내 AI가 부를 도구로 바꿉니다. 대상 시스템은 한 줄도 고치지 않습니다.
```

## 장면 3 — 수집 엔진 셋 (12초)

```
API 정보를 모으는 방법은 셋입니다. 포털이 공개한 명세를 읽고, 문서를 올려 뽑고, 화면이 부르는 호출을 관측합니다.
```

## 장면 4 — ①포털, 자연어로 찾기 (22초)

```
첫째는 포털입니다. 쓸 용도를 문장으로 적으면 시스템이 포털을 검색해 목적에 맞는 API만 골라 체크합니다. 왜 골랐고 왜 뺐는지도 한 줄씩 답합니다. AI가 쓸 도구를 AI가 고르는 것입니다.
```

## 장면 5 — ①포털, 수집 (8초)

```
고른 것만 모읍니다. 수집은 서버에서 돌기 때문에 창을 닫아도 계속됩니다.
```

## 장면 6 — ②문서, 올리기 (10초)

```
둘째는 문서입니다. 사내 회의실 예약 명세서를 올렸습니다. 공공 데이터만이 아닙니다.
```

## 장면 7 — ②문서, 지어내지 않는다 (16초)

```
보도자료도 올려 봅니다. 문서를 못 읽은 게 아닙니다. 읽었지만 엔드포인트가 없어서 도구를 만들지 않았습니다. 없는 API를 지어내지 않는 쪽이 더 중요합니다.
```

## 장면 8 — ③트래픽, 기록 (16초)

```
셋째는 관측입니다. 기록을 켜고 동네를 고른 뒤 단지를 누릅니다. 그때 화면이 부른 호출이 클릭과 함께 잡힙니다. 단지 목록과 실거래 내역, 두 개입니다.
```

## 장면 9 — ③트래픽, 후보 점수 (10초)

```
화면의 데이터를 실제로 나른 호출이 위로 옵니다. 로그를 남기는 호출은 감점돼 맨 아래입니다.
```

## 장면 10 — ④합류 (12초)

```
세 방식으로 모은 것이 한 프로젝트에 쌓였습니다. 게시, 트래픽, 문서. 어느 방식으로 모았든 여기서부터는 똑같습니다.
```

## 장면 11 — MCP 만들기 (8초)

```
후보를 골라 도구로 만듭니다. 파라미터와 필수 헤더가 함께 채워집니다.
```

## 장면 12 — ⑤실행, 턴 1 (14초)

```
이제 사람 말로 부릅니다. 명륜1가에 어떤 아파트가 있는지 물었습니다. 응답 원문은 저장하지 않고 구조와 샘플만 넘깁니다.
```

## 장면 13 — ⑤실행, 턴 2 (20초) ★

```
이번에는 단지를 지정해 실거래가를 물었습니다. 단지 코드를 모르니 목록을 먼저 부르고, 거기서 코드를 찾아 실거래를 조회합니다. 도구 두 개를 스스로 이어 부른 것입니다.
```

## 장면 14 — 마무리 (8초)

```
공공과 사내를 가리지 않고, 사람이 쓰던 화면을 AI가 부를 도구로 바꿉니다.
```

## 대사에 넣지 않은 것 — 의도적이다

| 넣지 않음 | 왜 |
|---|---|
| 소요 시간("몇 초 안에") | 실측 편차가 152ms ~ 5,380ms |
| 후보 순위("1위") | 두 API 가 동점이라 순서가 고정되지 않는다 |
| 구체적 거래 금액 | 화면에 뜨는 값을 말로 반복하면 어긋날 때 티가 난다 |
| 테스트 개수·진척도 | 보고서가 할 일이다. 영상은 동작을 보여준다 |

장면 12 의 "응답 원문은 저장하지 않고 구조와 샘플만 넘깁니다" 는 **약점을 설계로
설명하는 문장**이다. 그래서 화면에 단지가 하나만 보이는 것이 자연스럽게 읽힌다
(보고서 §3.3.4 데이터 최소 보존).

## 음성을 만든 뒤에 할 일

1. `docs/narration/s01.mp3` … `s14.mp3` 로 저장한다
2. 알려 주면 `ffprobe` 로 **실제 길이를 재서** 장면별 목표 초를 갱신한다
3. 그 길이에 맞춘 **녹화 지시서**를 만든다
4. 장면별로 화면을 녹화한다 (장면 8~9 는 확장이 필요해 손으로, 나머지는 Playwright)
5. `ffmpeg` 로 클립을 음성 길이에 맞추고 자막을 얹는다

**2번이 중요하다.** TTS 길이는 원고 길이와 정확히 비례하지 않는다 — 실제로 재야
화면과 음성이 어긋나지 않는다.

`ffmpeg` 이 아직 없다. `brew install ffmpeg` 이 5번의 전제다.
